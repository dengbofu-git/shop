# 管理员平台交易总览

2026-10-18 用户确认：首页展示平台交易总数据，“总流程”指交易总流水；三个导航为交易总览、Agent 管理、账号管理。2026-10-19 按用户要求移除 Agent 管理中的知识库提交占位入口。

- `/admin_panel.html` 为统一管理端外壳，默认展示交易总览；`#agents`、`#users` 在同一导航下嵌入 Agent 管理和账号管理。原功能页直达地址重定向到对应hash，`?embedded=1` 仅渲染内容，不重复导航和退出按钮。
- 平台有效角色且有 `data_view` 时默认进入交易总览，否则按 `user_manage` 进入账号管理，再按 `system_config` 进入 Agent 管理。无可用权限继续拒绝登录；不自动授予任何权限。
- `GET /v1/admin-panel/overview` 要求有效平台角色及 `data_view`；买家即使本来具有 `data_view` 也不得读取平台统计。响应禁止缓存；查询失败返回503而非零值。
- 总销售额计全额已付款商品金额，标准状态2/3/4、试单状态2/3/4/5/6/8、预售定金与尾款均已付且未取消；不含运费。全额支付订单数采用相同条件。
- 商家与平台共用 `orders/analytics.py` 的销售订单条件；商家按本店成交明细计算，统计周期与两端差异见[销售额核对](sales-reconciliation.md)。
- 交易总流水计标准已付及试单已付（含已退货）的商品金额和运费，以及预售已付标记的定金与尾款。退款没有独立记录，暂不冲减；预售运费不计入，不宣称为支付对账账本。
- 订单总量含保留的全部标准、试单和预售；每日趋势含今天及此前29个自然日，按上海时区的下单日期归集而非支付日期。状态分布分别使用各订单类型的状态字段，并显示未知状态剩余量。
- 买家／茶企账号按 user_type 计注册数量，剔除具有有效平台角色的账号；含停用账号。已删除订单／账号不计入。
- 前端展示真实接口数据，初始占位为破折号；空库返回零与30天补齐序列，失败清空旧统计并提示重试。图表附有可展开的每日明细，窄屏折行。

验证：隔离内存SQLite覆盖空库、标准／试单／预售金额、定金／尾款与退货取消、多类型状态、上海自然日、权限撤销、买家／供应商隔离、查询失败、导航与模板。新增统计不需要 Migration，不连接业务库执行测试或迁移。

嵌入验收：外壳允许拥有任一平台入口权限的有效平台账号，按实际授权选择可用内容；各功能接口继续独立鉴权。切换到总览时卸载iframe，避免后台轮询；hash切换和浏览器返回保持导航高亮，未知或无权限hash回到允许的首个功能。
