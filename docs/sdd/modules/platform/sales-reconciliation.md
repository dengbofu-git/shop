# 商家与平台销售额统一口径

2026-10-18，用户要求核对单个商家销售额高于平台总额的问题。只读核查确认：平台累计销售额为62220.00元；shangjia旧商家口径66659.00元，其中11笔标准待付款订单共6679.00元。排除后为59980.00元，93笔已付订单；另两家商家在统计周期内销售额为0。当前订单头金额与商品明细之和没有发现不一致记录。上述为当次数据库快照，不保证以后数值不变。

## 规则

- 销售额的订单条件集中于 `orders/analytics.py:sales_eligible_orders`，平台和商家共用，订单币种须明确为CNY。标准订单状态2/3/4、试单状态2/3/4/5/6/8计入；预售须定金和尾款均已付款且未取消。待付款、仅定金、已退货试单和已取消预售不计入。
- 平台累计销售额取符合条件的订单商品总额，不含运费；商家仅取符合条件订单中属于本店的历史明细数量乘成交单价，不分摊其他商家的商品或运费。
- 商家销售总额、月度销售趋势、品类占比、热销商品和销售区域金额采用同一已付明细集合；订单总量仍含待付订单，另外返回已付订单数。已付订单均额的分母为本店已付订单数。
- 商家统计周期保留近30／92／365天，平台为累计；均按下单日期归集。商家页面明确展示周期和付款范围，金额保留两位小数，避免使用万元简写掩盖差异。
- 最近订单即使是一张跨商家订单，也只展示本店明细金额和商品数量；其状态保留原订单状态，不将待付订单伪装为已付销售。
- 月度趋势按上海自然月生成最近6个互不重复的月份，且受所选统计周期限制；不再使用减30天推算自然月。

## 商家统计范围与完整性（2026-11-03）

本节补充商家只读统计与页面解释契约，金额资格继续执行[人民币规格](../../architecture/currency.md)。文内2026-10-18的金额与HTTP结果属于当次历史快照，不能作为当前数据或本节验收结果。

原销售资格中的状态条件与币种条件分开描述：状态合格仍为标准单状态2/3/4、试单状态2/3/4/5/6/8、预售定金和尾款均已付款且未取消；财务统计仍须订单币种明确为CNY。状态记录不因新增统计元数据成为独立支付流水或真实渠道付款凭证。待付款、仅定金、已退货试单及已取消预售不得计入币种待核验范围。

`GET /v1/supplier/analytics` 在 `data.summary.sales_scope` 返回范围元数据，`GET /v1/supplier/insights` 在 `data.sales_scope` 返回同一结构。两者各自沿用本接口的商家归属与查询周期；同一订单含本店多条明细或混合店铺明细时，在本店仅去重计1笔。商家购买快照优先，快照缺失时沿用原商品当前商家回退；不纳入外店、周期外或状态不合格订单。币种分组使用原销售资格所依据的订单币种，不推断历史明细币种。

| 字段 | 契约 |
| --- | --- |
| `currency` | 固定为 `CNY`，表明财务统计基础币种 |
| `status_order_count` | 本店同周期内状态合格的去重订单总数，尚未按币种排除 |
| `cny_order_count` | 上述集合中订单币种为 `CNY` 的笔数 |
| `unknown_currency_order_count` | 上述集合中订单币种为NULL或空字符串的笔数 |
| `other_currency_order_count` | 上述集合中订单币种非空且非 `CNY` 的笔数 |
| `financial_state` | `complete`、`partial` 或 `unavailable`，按下表由真实计数确定 |

计数字段均为非负整数，必须满足 `status_order_count = cny_order_count + unknown_currency_order_count + other_currency_order_count`。排除数量只披露笔数与原因，不把未知币种金额或其他币种金额相加、换算或标成人民币。

| 状态 | 条件 | 页面含义 |
| --- | --- | --- |
| `complete` | 未知及其他币种均为0 | 状态合格订单全部可纳入CNY财务统计；状态合格总数也为0时，保留真实零值，不另设 `empty` 状态 |
| `partial` | CNY笔数大于0，且未知或其他币种笔数大于0 | 显示实际CNY金额及笔数，同时明确仅统计CNY及排除的两类数量 |
| `unavailable` | CNY笔数为0，且未知或其他币种笔数大于0 | 有状态合格历史订单，但暂无可统计的人民币交易；金额及均额显示“暂无可统计”，CNY已付订单数保留实际0并标明范围 |

缺失或非法元数据（含计数、总和、币种或状态不一致）不得默认为 `complete` 或补造排除数。兼容旧接口时显示“统计范围信息暂不可用”，不能据此宣称真实无交易。加载、错误、账号切换及过期请求处理须清除旧范围提示，不能将其他账号的计数保留下来。

以上只新增范围解释，不改变原财务字段的类型、数值及统计资格，不改变完成率的原订单状态口径；未知币种不影响原履约状态展示。禁止为了恢复旧销售数字补填历史币种、付款时间、交易号或金额；如需更正历史事实，应先独立核验真实币种与付款证据，不由本次页面修正自动执行。本节不引入Migration。

验收需覆盖全NULL、空字符串、全其他币种、部分CNY、明确CNY零金额、空商家及仅不合格状态订单，并核对去重、混店、购买快照、周期、子类型和两个接口位置。前端需覆盖中英阿、零值与暂无可统计的区别、非法／旧接口降级及加载错误清空。本节定义验收要求，实际命令、结果和运行启用由对应证据单独记录。
