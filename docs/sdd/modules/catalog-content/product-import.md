# 商家表格批量商品导入

规格版本 0.1.1；日期 2026-10-28（Asia/Shanghai）。归属 CAP-CAT-002／FEAT-005，关联 CAP-FUL-001。用户明确要求先在创建商品页面提供简单入口，首期支持 XLSX、CSV；本切片不开放 Agent、PDF/OCR 或任意业务写工具。以下新增、未上架、整批原子提交等为本轮实现的保守规则，不能解释为其他商品维护规则已完成评审。0.1.1按用户反馈移除通用导入中的内部进价字段。

原文件不落公共静态/媒体目录，也不保留原始二进制；任务保存文件名、SHA256、版本、规范化行、错误、过期时间及成功行到SPU/SKU的映射。预览不会创建商品。无后台Worker；首期对有界小文件同步解析，不宣称大文件吞吐量、后台队列或跨格式自动字段推断已完成。到期任务阻止提交但不自动物理删除，后续保留期限与清理策略另行确定。

## 接口合同

前缀 `/v1/goods/merchant/imports`。所有接口要求商家认证，响应no-store；错误使用真实HTTP状态和`{code,error}`，不返回数据库原始异常。

| 方法/路径 | 输入与行为 |
| --- | --- |
| GET `/template?format=xlsx\|csv` | 下载固定中文表头模板，示例行须替换；不接受身份参数 |
| POST 根路径 | multipart：唯一file和UUID request_key；建立ready或invalid任务，返回逐行候选与错误；结构错误400/超文件上限413 |
| GET `/<UUID>` | 返回本人任务、行号、规范化字段、错误数、摘要、过期状态、提交结果 |
| POST `/<UUID>/commit` | JSON仅review_digest；ready且未过期且全行有效才提交；冲突409，不存在/不可见404；成功或幂等重放200 |

模板表头：商品名称、分类、规格名称、品牌、商品介绍、售价、库存、市场价、币种。兼容这些字段对应的固定英文名；未知列、重复列、无表头数据均拒绝，不静默丢弃。空白行不导入；500行上限也约束文件中间的空行/格式行，须移除多余格式。

解析版本升级为products-sheet-v2，旧未确认任务不得继续提交；旧已完成回执仍可读取，但按现行字段白名单投影，不返回成本。既有SKU.cost_price为历史非空列，新导入仅保存既有兼容占位0，不代表实际进价为0，也不得据此推断利润。此改动不迁移或改写已有成本数据；独立成本管理不在本切片范围。

## 服务与数据库边界

`product_import_parser.py`不导入Django/ORM、不联网；`product_import_views.py`负责认证和文件边界；`product_import_service.py`为可信应用服务，拥有短事务及库存服务调用。Agent未接线。未来调用方只通过业务接口，不能将ORM、SQL、管理命令或数据库凭据作为Agent工具。

任务表为 `goods_product_import_job`，新增 `goods.0012_productimportjob`；不改历史迁移、现有商品或库存。锁顺序为当前商家→任务，序列化同商家的导入；与其他旧商品接口并发创建同名的全域唯一性不是本切片保证。成功时SPU、SKU、账本、库存日志、结果回执原子提交，不在跨库事务中操作知识库。

XLSX使用固定openpyxl3.1.5与defusedxml0.7.1，ZIP成员/解压总量与XML预检后只读读取，关闭工作簿；方案参考[只读模式](https://openpyxl.readthedocs.io/en/stable/optimized.html)和[XML安全说明](https://openpyxl.readthedocs.io/en/stable/#security)。

## 迁移、启用与回滚

代码、独立测试服务验收与业务启用分开。迁移在无业务数据的临时MySQL8实例验证。按仓库规范，本轮不自动执行任何业务库迁移或重启8000；启用须单独授权，通过受控应用服务备份/迁移新增任务表并重载服务，不由Agent直连数据库。

回滚应用入口不删除已导入商品；已确认导入的商品按正常商品管理流程维护。迁移回退会丢失任务与幂等回执，生产回退不能自动执行，需保留备份及业务方案。
