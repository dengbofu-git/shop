# 买家商品卡片操作分层

日期：2026-10-18；当前增量更新于2026-10-20（web0.21.1）。用户要求修正卡片操作重叠和入口不明显，并在后续移除两个次操作入口；涉及 CAP-CAT-001、CAP-CAT-004、CAP-PLAT-002。不新增商品或交易后端接口。

## 当前问题与目标

用户提供的截图中，悬浮说明盖住采购按钮，收藏位置与遮罩混在一起；整卡点击又触发采购，与预览、详情和收藏争用同一块区域。旧精选“溯源”链接实际上进入详情，采购列表按钮仅弹提示而未执行采购车处理。

- RULE-CARD-001：图片与商品名使用明确的详情链接；其余卡片空白及说明文本不绑定采购或导航。
- RULE-CARD-002：价格下方固定主操作行，显示实心“加入采购车”和独立描边“收藏／已收藏”；收藏继续复用当前SKU状态、处理中禁用及错误重试，点击不触发采购或详情。
- RULE-CARD-003：按2026-10-20用户要求，首页精选与商品采购卡片移除“快速预览”“溯源”入口及整条次操作行，不保留空白分隔区域。主操作行和商品详情链接保留，手机无hover也能操作。
- RULE-CARD-004：精选与采购列表共享操作行为；只有采购按钮调用现有采购车逻辑，登录用户走原采购API，匿名用户走原本地采购车。现有价格／币种口径不在本次重定义；不改库存或支付逻辑。
- RULE-CARD-005：完整商品信息通过图片／商品名进入详情查看；旧预览弹层的规则仅对应历史版本，当前卡片不再提供预览入口。
- RULE-CARD-006：溯源演示页面、专用JS/CSS与路由已按2026-10-18要求删除；2026-10-20继续删除卡片上的禁用占位按钮。当前卡片不展示溯源入口。
- RULE-CARD-007：主／次按钮触控高度至少44px，提供可见键盘焦点，窄屏可换行且不覆盖；保留中英阿文案及RTL。推荐商品的小卡片不在本次重新排版范围，原独立收藏入口保留。

## 实现与验证

2026-10-20（web0.21.1）：两个卡片生成器均不再创建次操作行，删除对应分隔线和留白的来源；图片／商品名详情、采购及收藏入口保持原行为。更新两页静态缓存参数，定向验证卡片渲染及现有分类／分页；以下为历史实现与验收记录。

2026-10-18后续界面增量：移除全部商品卡片中固定写死的GI徽标；不能将先前徽标存在视为已取得地理标志认证。溯源仍为禁用占位，商品名／规格展示与10件分页见[页面补充交互](../platform/interface-increments.md)。早期web0.8.x测试与截图只覆盖当次实现，不覆盖当前web0.14.0所有变化。

精选由 `client/static/js/buyer-workbench.js` 生成；采购列表由 `buyer-products.js` 生成。采购点击与预览统一委托给前者；删除采购列表只弹提示的重复处理。`buyer-favorites.js` 优先将按钮挂到 `.product-actions-row`，没有主操作行的推荐卡片继续使用原容器。样式在买家共用的 `buyer-favorites.css`，删除 `buyer-workbench.css` 内旧悬浮层与整卡样式；两个页面和共用头部更新缓存参数。当前web版本0.8.1，溯源已按后续要求置空禁用。

验收：检查桌面和375px内容宽度下无按钮交叠；点击说明不加车，预览只打开弹层，Esc关闭并还原焦点；检查图片／标题链接与溯源禁用状态；采购列表显示两个主按钮与两个次入口，中英阿切换正常。初次重设计证据见[验证记录](../../evidence/2026-10-18-card-actions/verification.md)，其中旧链接及截图仅对应0.8.0，不代表0.8.1仍有溯源跳转。截图不构成完整无障碍认证或真实交易验收。
