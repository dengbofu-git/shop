# 商家首页经营概览与待办分区

日期：2026-10-22，web0.27.0。用户确认将上下重复的订单状态区块拆为经营结果和当前操作，复用既有商家统计及工作台动态接口，不修改订单、结算、消息的写入规则。

## 展示职责

- 上方“经营概览”固定近365天、按下单日期归集，只展示已付销售额、已付订单数、平均订单金额、订单完成率。四张卡片只读，不跳转订单或数据中心，也不夹带待付款、待发货、待收货状态。
- 已付销售额、订单数和均额沿用 `GET /v1/supplier/analytics?period=year` 的 `total_sales`、`paid_order_count`、`avg_order_amount`，金额为本店商品金额、不含运费，依据[销售对账口径](../platform/sales-reconciliation.md)。完成率及完成数使用该响应已有 `completion_rate`、`completed`、`order_count`，不另造付款或履约规则。
- 下方“当前待办与动态”复用 `GET /v1/supplier/workbench-feed`。只显示真实待发货订单、待结算账单、未读咨询；未读咨询按会话计数，合计只含这三类，待付款不属于商家待办。零值显示“无待处理”，允许进入对应列表核对。
- 商品审核和独立售后工作流未接入，首页不显示其占位项目；不将商品上下架等同审核，也不把试单退货当作独立售后工单。
- “最近动态”按接口现有顺序最多展示5条本店订单、物流及买家咨询记录。显示记录更新时间／消息发送时间，不把当前状态伪装成历史事件通知；无数据显示空态，失败显示错误和重试。

## 交互与布局

经营指标首屏读取期间显示破折号及aria-busy，失败不伪装成零；可重新加载。真正无订单的商家显示零。重试及返回工作台首页重新读取统计，旧请求不能覆盖后发请求，账号变化时不渲染旧账号响应。切换中英阿保留已加载数据并更新标签及数值格式。

宽屏经营指标四列；中等宽度弱化装饰图标、优先保证数值完整；1050px以下两列、600px以下一列。待办与动态双栏按内容排布，900px以下单栏。待办使用数量、事项及处理提示，零值弱化；动态文字最多显示两行，完整文本仍保留在DOM，可进入对应业务页面。保留侧栏作为完整业务入口，不增加全局重复导航。

实现：`merchant-overview.js/css`负责经营结果；`supplier-workbench.js`复用已有统计请求；`merchant-workbench-feed.js/css`继续负责真实任务、动态、超时、可见刷新及业务跳转。数据中心和其他市场洞察区块不在本次改动范围，不将其推算型内容当作本次真实指标。
