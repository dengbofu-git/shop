# 商家智能助手入口与后续能力边界

2026-10-18源码对账。能力 CAP-MER-004 归 MOD-MER，代码组件 merchant_ai 0.1.0，页面由 web 提供。对应聊天“agent设计说明”和“agent-商家”。当前只是入口与模块初始化，后续经营功能仍为设计候选。

## 当前已实现

商家工作台侧栏打开 `/merchant_assistant.html?embed=1`；页面复用既有Django模板和JavaScript技术栈，嵌入时不重复工作台外壳，展示欢迎及未开放提示。输入和发送禁用。

`GET /v1/merchant-ai/status/` 使用 merchant_required 和活跃账号检查；返回模块版本、initialized状态、`chat_enabled=false`、`model_connected=false`、`capabilities=[]`。商家身份来自认证上下文，不从页面参数或模型自报ID取得。无模型客户端、任务图、会话表、聊天／上传接口或业务工具；不复用买家私有会话、订单查询接口或偏好。

## 预期验收

- 活跃商家能从侧栏正常打开嵌入页，状态接口返回正确空能力信息。
- 匿名、买家及停用账号不能通过状态接口取得商家能力。
- 输入及发送保持禁用，没有浏览器绕过后可调用的聊天／上传接口。
- 新页面路由需要服务加载；历史404由旧的noreload进程未加载路由引起，重载后曾验证恢复，不作为当前端口状态保证。

## 尚未实现的候选

2026-10-28确认的[模型 Agent 数据访问规范](../../architecture/agent-data-access.md)同样适用于未来商家模型助手。开放前必须通过 MCP 和可信商家上下文取得授权数据，不能从模型参数选择商家或直接复用买家私有工具；本次仅追加架构约束，不启用聊天、模型、上传或写入能力。

TXT／PDF／Excel解析与批量建档／库存入库、商品长介绍、图片／视频生成、资料完整性检查、本人商家库存／订单查询和经营分析均没有在本轮实装。讨论过的候选流程为“生成草稿→商家预览修正→明确确认→服务端重新校验归属和版本→幂等执行”；这是后续设计输入，不是已批准的写入规则。

真正实施前需明确商品建档与库存入库区别、数量与销售单位、仓库授权、账本和SKU库存一致性、文件来源定位、异步任务、素材归属及费用。模型不得直接修改库存或绑定商家以外的商品。暂无相关Migration或运行验证。
