# 平台商品与商家店铺页面首版

日期：2026-10-20。CAP-MER-005，来源 FEAT-036。用户在当前聊天确认“保留运营、买家、商家三个角色入口；买家端新增店铺展示，商家端新增店铺页面管理”，并授权“先初步实现”。此文记录该首版规则及实现范围，不自动推进其他能力阶段或授予部署／迁移业务库授权。

## 范围与页面

- REQ-STORE-001：平台首页和采购列表继续聚合多商家商品；商品卡片及详情展示所属店铺，已发布店铺可点击进入 `/store.html?merchant_id=<id>`。未发布标“店铺筹备中”，历史无商家归属商品标“暂未登记店铺”，不伪造所属店铺。
- REQ-STORE-002：买家访问商家主页可见店铺横幅、Logo、名称、简介、欢迎语、店主推荐、本店全部商品和介绍；保留返回平台、商品详情、原采购车与收藏入口。
- REQ-STORE-003：商家工作台在商品管理之后新增“店铺页面管理”，通过现有 iframe 加载 `/merchant_store.html?embed=1`。固定模板编辑，支持桌面／手机预览，预览不触发采购、不改变登录身份。
- REQ-STORE-004：首版一个商家账号对应一个 StorePage，以商家 ID 作为公开定位；不新增登录入口、多店租户、优惠券、店铺关注、独立域名或自由拖拽装修。

## 业务与权限规则

- RULE-STORE-001：管理接口从 Bearer Token 读取身份，只允许活跃 merchant 或已有 supplier 角色；不接受自报 merchant_id 修改归属。公开响应只投影已发布内容，不包含草稿、账号名、邮箱、手机号或认证数据。
- RULE-STORE-002：店名 50 字、简介 200 字、欢迎语 100 字、故事 5000 字；纯文本渲染。保存草稿不改变公开快照；发布要求店名非空，明确复制草稿为公开版本，并同步现有账号店名／简介。既有资料仅用于首次填充，不建立独立的第二套商家身份。
- RULE-STORE-003：推荐最多 8 个 SKU，顺序由商家调整；保存／发布检查全部商品属于当前商家。公开时重新按本店、上架且 SKU.stock>0 过滤，不使用已发布快照中的价格、库存或商品内容。不改变现有平台 index 库存口径，不把此口径宣称为统一库存权威。
- RULE-STORE-004：店铺下线只关闭主页和店铺入口，保留草稿／上次发布快照，不连带下架商品；停用账号或不再拥有商家身份时不能公开访问店铺。删除／转移／下架／售罄的推荐商品实时排除；再次发布仍需清理已删除或不属于本店的引用。
- RULE-STORE-005：保存、发布、下线携带 revision；服务端事务锁定店铺行，版本不符返回 409，不覆盖其他页面的新内容。前端保留本地内容并提示重新加载；没有静默自动重试写入。GET 不创建店铺数据。
- RULE-STORE-006：Logo 最大 4MB、横幅最大 8MB，仅 PNG/JPEG/WebP，最多 2000 万像素；服务端解码并重新编码 WebP，剔除元数据，以随机名存入本商家素材目录。页面配置仅允许本商家目录的本地素材 URL。上传本身不保存或发布页面；不做自动清理或删除历史素材。
- RULE-STORE-007：店内搜索、分类、最新／销量／价格排序、每页10项均在后端商家过滤之后进行；平台继续全量聚合。购买、收藏、身份、价格换算与交易行为沿用当前入口，不在本次统一其他页面的币种差异。销量排序读取现有 SKU.sales，不生成虚构销量。

## API 契约

| 方法与路径 | 身份／返回 |
| --- | --- |
| GET `/v1/supplier/store-page` | 本人商家；draft、revision、is_published、has_unpublished_changes、published_at、public_url；无写入 |
| PUT `/v1/supplier/store-page` | `{revision, content}`；保存整个合法草稿，revision+1 |
| POST `/v1/supplier/store-page` | `{revision, action: publish或unpublish}`；发布已保存草稿／下线，revision+1 |
| POST `/v1/supplier/store-page/image` | multipart kind=logo或banner、image；返回本商家图片 URL |
| GET `/v1/stores/<merchant_id>` | 公开；已发布页面投影、实时推荐、可见商品数量、当前茶类 |
| GET `/v1/stores/<merchant_id>/products` | 公开；q、catalog_id、sort、page，固定 page_size=10；返回 data 和 pagination |

content 字段：name、summary、welcome、story、logo_url、banner_url、featured_ids。API 统一 `{code, data}` 或 `{code, error}`；401未认证，403角色／激活不符，400输入不合法，404店铺不存在／未发布／已下线，405错误方法，409并发冲突；所有新接口禁止缓存。公开 GET 不写浏览历史、不调用模型。

## 模块与数据库

supplier 拥有 StorePage、迁移、校验、管理／公开 API；goods 的公开商品投影增加 merchant 摘要并预加载关系；web 拥有两页、共享渲染及现有卡片／侧栏的精确增量；core 注册页面和公开 API 路由。goods 增加 supplier 读取依赖，supplier 仍依赖 goods 可售事实；无服务拆分、跨库事务或模块导入时互相执行服务。

新增 `supplier/migrations/0002_storepage.py`，只创建 StorePage 表及商家一对一关联，不回填现有商家或改写商品／订单。必须先应用新增迁移再加载新服务代码，goods 商品查询也会预加载店铺表。先在隔离 MySQL 测试库验证；业务数据库迁移及服务部署须另行授权。回滚服务前应协调停止页面写入，保留该新增表以防草稿丢失，不自动逆迁移。

## 可观察验收

- AC-STORE-001：两家店的商品在平台同时出现，卡片和详情跳入各自店铺；历史无归属商品不会产生错误店铺链接。
- AC-STORE-002：买家和匿名不能修改；商家不能以参数、推荐商品或素材 URL 写入别店内容；公开响应无私有字段。
- AC-STORE-003：首次保存后店铺仍未公开；发布后可访问；保存新草稿不改变公开内容；再次发布生效；下线不改变商品上下架。
- AC-STORE-004：推荐顺序保留，下架／删除／无库存商品不公开；店内筛选及分页不跨店且无重复遗漏。
- AC-STORE-005：两个编辑页面并发操作，旧 revision 返回409；未保存内容可预览，预览采购禁用；窄屏可操作且无水平溢出。
- AC-STORE-006：有效图片上传后重编码，错误／超限类型被拒绝；店铺名称和故事按文字显示，不能执行 HTML。

测试：`supplier.test_store_pages`、`client/tests/storefront.test.js`，并回归 goods、原商品分类／分页及商家商品预览测试。实际执行结果与覆盖范围见 [验证记录](../../evidence/2026-10-20-store-pages/verification.md)；开发／验证不等于提交、部署或发布。

## 2026-10-20 推荐商品搜索交互

按用户截图反馈，将管理页商品长下拉框替换为“搜索本店商品”。复用已认证的本店商品响应，在当前页面按商品名、规格、简介做不区分大小写的关键词包含匹配；空格分词需全部匹配。不改后端授权、商品范围、推荐持久化或公开店铺排序。

输入后显示匹配总数与最多6条结果；超过6条提示细化关键词，空词不展开全部商品，无匹配有明确提示。结果直接“添加”，已添加项禁用且标记，达到8件后禁用添加并提示；原推荐顺序、移除、草稿／发布不变。Enter只执行当前筛选，不提交表单；Escape清空并收起结果。使用纯文本DOM渲染商品字段，按钮可键盘访问。web0.23.1；实际验证见[搜索交互验证](../../evidence/2026-10-20-store-pages/recommendation-search.md)。
