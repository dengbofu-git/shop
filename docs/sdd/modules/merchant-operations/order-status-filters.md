# 商家订单状态分类

日期：2026-10-19。关联 CAP-MER-001／FEAT-012；实现模块 web 0.19.0。此为当前页面增量，不改变能力阶段和交易生命周期规则。

## 展示与分类规则

- 页面为 `merchant_orders.html`，兼容独立访问及工作台 `embed=1` 嵌入；在“我的订单”标题下方显示状态分类。
- 默认“全部”；常驻分类为全部、待付款、待发货、待收货、已完成，各显示订单笔数，零订单仍保留常驻分类。
- 从现有 `GET /v1/supplier/orders` 获取当前商家完整订单，不传 `limit` 和 `status`；数量基于同一份响应计算，切换分类在本地完成，保持接口的时间倒序。
- 分类优先使用 `status_text`，仅将“订单完成”展示为“已完成”；缺少文本时按既有基础状态 1／2／3／4 回退。试用中、待付定金、待付尾款、已取消等实际返回的其他状态单独增加分类，避免将基础状态相同的特殊订单错误归入标准订单阶段。
- 列表展示订单号、状态标签、金额、数量、收货人、电话、地址、时间和操作；窄屏横向滚动，状态／电话／订单号不拆行，地址按正常文本换行。
- 无订单、所选分类无订单、加载中及请求失败分别展示提示；失败可重新加载。保留已加载的数据时，显示刷新失败，禁用旧数据上的操作直到成功重载。

## 状态切换与现有边界

- `filter=unshipped`／`unpaid` 分别选中待发货／待付款；支持基础状态数值及状态中文名，选中分类写回当前 URL，保留 `embed` 等参数。浏览器刷新保持分类。
- 删除仍需确认；发货／删除沿用原有 POST 路径，2026-10-20起动作采用服务端 `can_ship`／`can_delete` 标记，支持实际子类型状态；旧响应缺少标记时才回退基础状态。后端继续重新校验认证、商家归属、库存和生命周期。操作中禁用按钮，成功后重新读取列表与分类数量；选中分类的最后一单消失后保持该分类并展示空态。
- 特殊订单状态文本来自现有子类型模型；发货后重新查询真实文本，不在页面直接假定其已变成“待收货”。2026-10-20交易修复后，试单／全款预售按自身状态发货，历史混合单不显示发货／删除按钮并提示需平台处理，实际接口同时返回409保护；详见[订单操作保护](../trade/merchant-order-isolation.md)。
- 收货信息及状态文本作为文本转义，不作为 HTML 执行。金额沿用原列表人民币展示口径，本增量不增加币种转换。
