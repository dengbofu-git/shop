# 商家工作台待办与消息

日期：2026-10-22。归属 CAP-MER-002／FEAT-013，保留现有能力阶段。范围仅为首页“待办与消息”，其他看板统计口径见[销售额核对](../platform/sales-reconciliation.md)。

## 数据与权限

新增只读 `GET /v1/supplier/workbench-feed`，使用当前登录令牌，不接受客户端指定商家。账号必须有效且统一权限路由指向商家工作台；匿名／停用账号返回 401，买家／平台角色返回 403，其他方法返回 405。响应禁止缓存。读取不修改会话已读位置、订单、结算或物流状态。

订单归属优先使用 `OrderGoods.merchant_snapshot`；仅历史快照为空时，沿用商家订单列表的当前商品商家判断。本接口不猜测或回填历史归属。一个订单包含多条本店商品时，只统计一笔订单。

| 待办 | 真实来源与口径 | 入口 |
| --- | --- | --- |
| 待发货订单 | 全部本店待发货订单：标准单 `status=2`；试单子表 `status=2`；预售子表 `status=4` 且定金、尾款均已支付 | 商家订单管理，选中待发货分类 |
| 待结算账单 | `SupplierSettlement.supplier` 为当前商家且 `status=pending` 的记录数 | 商家结算记录，可查看各笔状态 |
| 未读咨询 | 当前商家会话中，买家发送且消息 ID 大于 `merchant_read_id` 的不同会话数；多条未读消息只算一项待办 | 商家买家咨询页面 |
| 待审核商品 | 暂无持久化商品审核流程，返回 `null`，保留模板及后端 TODO 注释占位，不显示数字或跳转 | 待后续真实审核模型接入 |
| 待处理售后 | 暂无独立售后申请及处理模型，返回 `null`，保留模板及后端 TODO 注释占位，不显示数字或跳转；试单退货状态不等于售后工单 | 待后续真实售后模型接入 |

总数为前三项之和。待办覆盖全部未完成记录，不受销量看板近一年／月度等统计周期影响；不再由 `/analytics` 中的辅助待办值覆盖。总数是待办操作数量，不表示互不重叠的订单数。

## 最新消息

该区域展示现有业务记录，尚未建立独立通知事件／通知已读模型：

- 本店买家发来的最新 4 条咨询，正文截取最多 160 字，点击进入对应会话。
- 本店最近更新的 5 笔订单，展示订单号和真实订单类型对应的当前状态，点击进入商家订单管理。
- 本店最近更新的 4 条运单，展示运单号与物流状态。历史混合商家订单的运单无法确认由哪家发货，排除这类记录，避免错误归属。
- 合并按记录时间及 ID 降序，接口最多 8 条，当前首页显示前 5 条；没有记录显示空状态。订单／物流时间为其基础记录的更新时间，咨询为发送时间，不伪装成“刚收到新订单”或“刚审核通过”等通知事件。

接口不返回买家收货地址、手机号、全量账户资料或其他商家的咨询。正文使用纯文本渲染；只允许当前工作台的订单、结算、咨询入口，不能跳入买家工作台或外部地址。

## 展示与刷新

沿用现有绿茶色卡片布局，支持中文、英文、阿拉伯文。加载中、请求失败、真实零值与空消息分别显示；未接入业务仅留代码注释占位。首次加载、手动刷新、返回工作台首页、页面重新可见时请求；首页可见期间每 60 秒更新一次，请求 12 秒超时，错误允许重试。

刷新清除旧显示；过期请求或切换账号前的响应不得覆盖当前结果。离开页面取消响应接收与定时器，浏览器往返缓存恢复后重新初始化。同源 iframe 保持当前标签页身份，入口不创建或切换账号。
