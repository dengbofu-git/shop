# 用户昵称与咨询展示

日期：2026-10-22。实现模块 users、engagement、web、core；本轮实现及隔离验证完成，已获用户单独授权并在本地业务库启用。验证见[记录](../../evidence/2026-10-22-user-nickname/verification.md)。

## 规则与入口

- 登录账号与昵称分开：新增 `UserProfile.nickname`，可空、默认空字符串，最多30个 Unicode 码点。昵称允许重复、随时修改和清空，保存时去除首尾空白，拒绝控制字符。昵称不是身份凭据。
- 买家和商家个人信息页提供独立“保存昵称”操作，不依赖邮箱、手机号填写或基本资料表单校验；支持中文、英文、阿拉伯语，以及加载、保存、失败重试和账号切换保护。
- 商家咨询列表与聊天标题显示买家当前昵称；未填写或清空时恢复原脱敏账号名。相同昵称仍以独立会话编号区分，保留原会话及参与者权限。
- 买家咨询继续显示店铺名称；商家个人昵称不修改店名。公开商品评价继续使用既有脱敏作者名称，本次不扩大昵称公开范围。
- 昵称按纯文本渲染，不执行 HTML；不写入登录用户名、令牌、采购车键或订单归属。已有消息内容和收发对象不改写，昵称修改后会话列表刷新同步当前聊天标题。

## 接口与兼容

- 现有 `GET /v1/users/<username>/profile` 增加 `data.nickname`。原联系方式 PUT 不修改昵称。
- 新增同地址 PATCH：仅接受 JSON `{"nickname":"茶友"}`，仅当前有效账号可以修改自己的昵称；原始 JWT 与 Bearer 头兼容。缺少授权返回401，其他账号路径返回403；非字符串、字段缺失、额外字段、长度或控制字符错误返回400。
- 成功返回 `{"code":200,"data":{"nickname":"茶友"}}`，响应禁止缓存。不能通过此接口修改角色、用户名、店名或联系方式。
- 旧后端响应尚无 nickname 时，页面禁用昵称编辑并提示“昵称功能尚未启用”，防止误报保存成功；不会将旧账号名自动存为昵称。

## 存储与启用

- 新增 `users.0008_userprofile_nickname`，不改历史迁移、不回填现有昵称。MySQL 对新字段指定 utf8mb4，连接同样使用 utf8mb4，支持表情字符；不转换其他已有列。迁移含 MySQL DDL，设置 `atomic=False`。
- SQLite 用于快速隔离回归；真实 MySQL 隔离库用于验证建库、迁移及保存，测试结束销毁。2026-10-22用户单独授权后，本地业务库已备份并执行0008，8000后端已重启；13个账号原有列摘要一致，昵称默认空。
- 经单独授权后，先备份并验证备份，再执行限定的 `python manage.py migrate users 0008_userprofile_nickname --database default`，核对原用户字段与数量未变化、新列及迁移记录，最后重启本地后端并只读验收。
- 不自动执行其他 App 待应用迁移，不自动回退或删除昵称列；迁移失败先停止并检查，恢复数据库须另行授权。用户自行编辑真实昵称，不由本次实现代填。
