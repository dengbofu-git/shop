# 按商家独立下单与订单操作保护

日期：2026-10-20。用户在先交付已有更新、创建 PR 后，明确要求修复[多商家验证](../../evidence/2026-10-20-multi-merchant/verification.md)发现的 5 项交易问题。实现模块：orders 0.2.0、supplier 0.3.1、web 0.24.0。本文补充当前订单与店铺规则，不提升其他能力阶段。

## 下单与支付

- 一个新订单只能包含同一商家的商品。采购车同时选中多个商家时，服务端按商家 ID 分组，创建多笔独立标准订单、明细和支付链接；同一家店的多个 SKU 合并在其订单内。单品立即购买仍只生成一笔。保留时间戳加数字随机后缀的26位订单号格式。
- 结算和预览从令牌确定当前活跃买家，路径账号必须匹配；地址必须属于本人且未删除。采购车的数量和选择状态从服务端读取，客户端只可传入选中的 SKU ID，不可覆盖价格或数量；立即购买数量必须为正整数。
- 拒绝重复／缺失 SKU、空选择、无有效商家、下架、无效价格及超库存数量。库存资格沿用 `max(SKU.stock, 各仓 available_quantity 汇总)`，不在本次改成库存账本优先，也不引入下单预留或付款扣减。
- 商品事实在事务内读取和锁定，金额使用 Decimal。所有商家订单及支付链接要么一起成功，要么整批回滚。生成支付链接失败不能留下部分商家订单，也不能提前清理采购车。
- 成功提交后，仅原子移除本次校验值仍未变化的已选采购车项；未选项和并发改动保留。Redis 清理失败记录安全错误事件，不回退已提交订单；数据库与 Redis 不是分布式原子事务，尚无持久下单幂等键。
- 创建接口 `data` 新增 `orders`、`order_count`、合计金额和数量。每笔含独立 `order_id`、`total_amount`、`carts_count`、商家公开名称／ID、`pay_url`。仅单笔响应继续兼容顶层 `order_id`／`pay_url`；多笔时不伪造合并付款链接。
- 支付页面列出每家店的订单和金额，买家选择一笔后跳转其支付链接；其余待付款订单从“我的订单”继续付款。`payment.html` 与 `gopay.html` 复用同一模板和脚本。继续付款只读取本人未付款标准订单，不重新创建，也不对历史混合单生成整单支付链接。
- 保持现有支付金额及币种口径，不对多笔订单收取额外费用，不引入合并付款、父支付单或真实支付回调安全重构。订单和支付入口中的商家名称仅为公开展示信息，不返回商家账号或联系方式。

## 商家发货／删除

- 先锁订单头，再核对所有明细的商家集合必须恰好为当前商家。完全不属于本人返回 403；包含本人但混有别家或无归属明细的历史订单返回 409，发货／删除均不改其状态、明细和库存。
- 历史混合单需要平台另行制定拆分处理方案。本轮没有新增后台拆分按钮、自动回填或迁移，也不静默改写实际业务订单。
- 标准订单从基础状态 2 到 3；试单从 TrialOrder 状态 2 到 3；预售必须定金、尾款均已支付且 PreSaleOrder 状态 4，发货后到 5。子类型不依赖历史基础 status，也不覆盖其值。
- 子状态行与订单头均受锁保护；全部商品按固定顺序扣减库存，任一行失败则整笔发货回滚。非正数量、缺失子记录、重复发货、未付／部分付款／取消或非待发货状态均拒绝。子类型发货同步更新订单头更新时间。
- 删除仍按类型判断未付款／已结束状态：标准 1／4；试单 1／7／8；预售 1／6／7。不能用陈旧基础状态删除仍在试用或履约中的子类型订单。此规则不是新增退款／财务对账证明。
- 商家订单列表新增 `can_ship`、`can_delete`、`requires_merchant_split`，页面按这些服务端标记展示／触发操作；接口收到请求后仍重新鉴权和校验，不能依赖按钮隐藏。经营看板的待发货、待收货、完成及待付款分类采用实际订单子类型状态。

## 验证与边界

新增 checkout 与商家动作回归，覆盖多商家分组、服务端事实、精确金额、整批回滚、归属、子状态、旧混合单、重复和并发请求；支付页面／商家列表有确定性前端联调。实际本地 MySQL 的 5 项原缺陷探针均以模拟数据执行并回滚，原始表指纹不变。详见[本轮验证](../../evidence/2026-10-20-order-isolation-fix/verification.md)。

原 75 项验证中的 5 项失败是修复前快照，不删除或改成通过。本轮不新增 Migration，不自动部署或把未提交业务修复加入先前的 PR #8；实际 Git、服务和验证状态以本轮记录为准。真实支付验签、金额／商户核验、回调幂等、退款、租户仓库、统一库存权威及销量自动累计仍不属于这 5 项修复的完成声明。

试单／预售本轮接通商家发货及商家状态展示；不扩展其定金尾款支付、试用结束或买家后续确认收货流程。
