# 按商家独立下单与订单操作保护

当前正文更新：2026-10-30。归属 CAP-TRD-001／CAP-TRD-002／CAP-MER-001。本文只维护商家隔离，库存、支付、取消与隐藏的唯一规则为[库存预留](stock-reservations.md)，金额与页面流程分别引用[人民币规格](../../architecture/currency.md)和[确认订单](checkout-confirmation.md)。本次删除已被替换的旧实现描述，不改变业务规则或历史证据。

## 下单和付款边界

- 新普通订单只含同一商家商品，多商家采购车按商家原子拆单；同店多个 SKU 合并。身份来自当前有效买家，路径账号和地址归属均重新检查。
- 服务端读取已选数量、价格、上架、商家状态及可售量；拒绝缺失／重复 SKU、无效价格和库存不足。库存使用账本优先规则，不再采用 max(SKU.stock, 仓库量)。
- 同一结算意图由持久幂等请求绑定；一店失败整批回滚。创建只返回独立订单及期限，不在创建事务内调用渠道或生成支付链接。付款针对已创建的本人有效订单单独发起，不提供合并支付承诺。
- 采购车清理由与结算同事务写入的持久任务及 Redis 游标处理，保留并发新增数量，失败可重试；不再采用“失败只记日志”的旧设计。细节统一引用预留规格。

## 商家操作范围

- 先锁订单并检查全部明细归属；优先购买时商家快照，无快照回退商品归属。完全非本店拒绝，混有别家或无归属明细的历史单拒绝整单操作。列表金额只计本店明细，不静默改写或自动拆分历史单。
- 标准单、试单、预售分别读取对应状态；历史子类型条件发货和库存消耗统一引用预留规格。支持历史发货不意味着开放新建、定金尾款、试用、退货和退款全流程。
- 买家未付普通单用取消关闭并释放；关闭或完成可隐藏且无交易副作用。商家兼容 delete 路由仅表达取消未付普通单并保留记录，不物理删除已结束或子类型订单。
- 当前接口的 can_ship、can_delete 等能力字段仅供展示；服务端收到动作后仍重新校验，不以按钮可见性授权。
