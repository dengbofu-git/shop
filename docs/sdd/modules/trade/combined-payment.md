# 合并付款与商家订单分摊

2026-11-04本地启用：用户授权后原生备份实恢复校验通过，仅应用pays.0001并恢复同源服务，75张原业务表内容保持、零待迁移；实际路由与前端资源通过。支付宝收款方校验仍未配置，返回503而不生成假付款链接，退款及商家分账不在本阶段。见[启用证据](../../evidence/2026-11-03-combined-payment/activation.md)。

规格0.1.0，2026-11-03。归属CAP-TRD-001／002／003。用户批准范围及取舍见[ADR0016](../../../adr/0016-combined-checkout-payment.md)。本页定义付款边界；[库存预留](stock-reservations.md)、[商家隔离](merchant-order-isolation.md)及[人民币规则](../../architecture/currency.md)继续有效。

## 买家流程

确认采购后点击“提交订单”，按商家创建独立订单。保存结果展示商家金额与查看订单入口，提供一个“合并付款”按钮。同一次结算的待付子单一次支付；不因刷新、支付配置缺失或付款失败重新下单。

创建结果增加payment_mode=combined、checkout_id与checkout_total_amount。后者是本次创建订单头金额总和，可能包含幂等回放中的已付／关闭部分；真正发起付款时，以服务端重新核验后的待付total_amount为准，不能把创建总额直接用于扣款。缺能力标识的旧响应只引导查看订单，不伪造合并能力。前端不展示锁、额度算法等内部解释。

POST `/v1/pays/checkout-payment`接收JSON `{checkout_id}`，身份来自当前有效买家，不接收客户端价格或任意订单列表。成功返回code=200及data，包含payment_id、checkout_id、CNY的total_amount、expires_at、status、payment_exception、orders、pay_url；商家明细含商品金额、运费及应付金额。旧订单type=5／gopay入口如有checkout关联，也转本组付款；历史NULL关联仍按原单付款及核验限制处理。页面核对待付状态、正金额、币种、截止和安全URL后才跳转。

## 不变量与并发

- PaymentOrder是一次固定渠道付款尝试，不是新的商家业务订单。PaymentAllocation保存购买商家及不可变金额。`sum(明细单价×数量)+freight=OrderInfo.total_amount`，分摊amount等于该订单头应付，父单total_amount等于分摊amount之和。
- 首次准备只纳入本人、同checkout、有效受管普通CNY待付子单；核对商品商家快照、币种、金额、预留数量及库存账本。已付或关闭部分排除；旧未知币种、未确认旧流水、缺快照或缺预留拒绝。
- 同一checkout最多一个pending尝试，截止取待付子单最早期限。生成后重复准备只复用固定成员、金额和截止，不自动新增其他金额尝试；成员或金额变化持久标记invalid并拒绝再签链接。
- 通知须先验签及app／seller／交易状态，金额须正数且精确到分。付款与旧单付款、取消、到期按买家→付款单→升序订单→升序SKU→升序账本／预留锁协调；全部有效子单在一个事务内确认，任一完整性失败不部分支付。
- PaymentReceipt的trade_no唯一且目标必须为付款单或旧订单之一。相同流水同目标同金额幂等；跨目标或改金额拒绝。父单正常到账后，子单status=2并记录paid_at，hold=paid，保留每店金额；旧子单unique payment_trade_no不复制父流水。
- 不同流水重复到账保留独立review收据，包括旧订单先确认一笔付款、随后另一笔真实到账的情况；不重复推进订单、消费库存或覆盖已有合法付款。GET返回页不确认付款。

## 变化、迟到及售后边界

子单关闭使关联pending父单invalid。父单创建前可按剩余有效待付订单准备；创建后不自动重开总额，以免旧渠道链接仍可付款。遇到这种情况需渠道核验处理，不能通过刷新假装旧链接已撤销。

已失效、已到期或子单变化后的可信完整到账记review。其余仍未付子单按payment_review原因关闭释放，并标记combined_payment_review；不计买家取消／超时罚点，不复活已释放库存，已合法付款保持。预留缺失等完整性错误则整次回滚，保留渠道重试机会。另一真实流水在已付父单到达，只标记该独立收据及父单待核验，合法子单可继续履约。

各店发货、收货和订单商品评价继续独立；商家只操作完整属于本店的子单。售后保留子单与分摊归属，本次不新增售后申请／审核、退款接口或自动退款，也不实现真实商家资金分账。当前项目仍由既有配置收款方收款，分摊快照不是商家到账凭证。

## 迁移与验收

新增pays.0001_initial创建PaymentOrder、PaymentAllocation、PaymentReceipt及约束。旧非空payment_trade_no仅回填legacy_reference，不改历史订单、金额、币种或库存，不补造验签记录。仅允许在隔离真实PostgreSQL验证；业务库备份、迁移和重启须单独授权，启动预检拒绝缺迁移的启用。

验收涵盖三店一次付款、非零运费只计一次、取消前后集合变化、重复／迟到／跨目标流水、缺预留整次回滚、独立发货、真实PG锁竞争及新旧入口；实际命令、源码绑定和未覆盖范围见[本次证据](../../evidence/2026-11-03-combined-payment/verification.md)。配置缺失时返回503，未调用真实支付宝、执行真实退款或验证商家到账。
