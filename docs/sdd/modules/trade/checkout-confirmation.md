# 确认订单、金额与付款入口

规格0.2.0，2026-10-23。归属CAP-TRD-001／002／003、CAP-PLAT-002；金额唯一依据[人民币规格](../../architecture/currency.md)，交易引用[预留规格](stock-reservations.md)。本文件完整合并布局、商品名称和新预留链路规则，删除旧USD基准条款。

## 需求与规则

- REQ-CHECKOUT-001：确认／付款／完成三步等分，不使用旧canvas箭头；桌面收货和商品在左、摘要在右，窄屏单列，长明细仅局部横向滚动。显示图片、SPU商品名、次要SKU规格、服务端单价、数量、行小计和费用范围。
- REQ-CHECKOUT-002：默认CNY，支持共用配置的外币参考显示；合法本页／采购车显示选择可保留，非法值回退CNY。切换不改变真实价格、支付币种或业务数据，不使用实时汇率承诺。
- RULE-CHECKOUT-001：基准为接口CNY原值；参考行小计由基准价乘数量换算，逐行取分，摘要合计已显示行小计。用Decimal／整数分，固定两位；件数和款数分开。商品小计、运费、税费、应付分开，未知费用不填0；历史币种未知不自动换算。
- RULE-CHECKOUT-002：切换仅重绘，不发送地址／预结算写请求，不清除地址、重取或覆盖数量；存储不可用不阻止切换。异步回包按当前选择展示，文字使用文本渲染。
- RULE-CHECKOUT-003：settlement_type=0读取服务端已选采购车，1为明确SKU和销售单位数量。确认仅提交地址、类型、必要SKU／buy_count及幂等编号，不提交参考换算金额决定交易。有效本人身份、本人地址、价格、上架、商家及可售量由后端重查；用户明确点击后按商家原子拆单及固定期限预留。相同意图重试一批订单，异店失败全部回滚；旧后端缺能力标记禁止创建无保护订单。
- RULE-CHECKOUT-004：本人有效地址默认首条，可改选；新增地址成功后刷新预结算并选中新地址，保留币种；失败保留表单。未加载、空商品或无地址禁用确认。

## 商品名称、付款和兼容

买家订单以SPU商品名为标题，SKU规格次要单列，重复不再显示。对象提供product_name、sku_name并保留name原规格含义，来自当前商品关联；本条不新增成交时名称快照。搜索同时匹配订单号、商品名、规格；详情仍指原SKU，数量、成交价及状态不因改名改变。

创建返回orders[]及逐单CNY金额／截止时间，不调用支付渠道；继续付款只针对已创建、本人有效未过期受管普通订单，不因刷新或渠道链接失败再下单。历史试单／预售状态阅读和条件发货不意味着新建、定金尾款及退款完整开放。未付款仅取消，关闭／完成可隐藏且不改库存。

页面orderConfirm.html使用局部样式，checkout-utils.js处理分金额及参数，orderconfirm.js异步装配；不恢复同步XHR、营销占位价或强制固定外币。真实支付配置、渠道币种和新订单币种快照设计另行评审，不从参考选择推断。
