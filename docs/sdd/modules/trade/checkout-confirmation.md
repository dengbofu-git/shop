# 确认订单布局与币种展示

日期：2026-10-18。关联 CAP-TRD-001、CAP-PLAT-002、Q-010；用户授权调整确认订单布局并修复无法切换的货币下拉框。实现模块web0.15.0，无后端、数据库或支付服务配置变更。

## 需求与规则

- REQ-CHECKOUT-001：确认页使用确认／支付／完成三个固定等分步骤，避免旧canvas箭头及固定宽度导致换行；收货卡片和商品明细在左，摘要在右，窄屏改为上下布局。商品图、商品名／规格、单价、数量及小计分列；长表格仅在自身区域横向滚动。
- REQ-CHECKOUT-002：本页币种下拉可选择USD、AED、SAR，沿用采购车参考比例1／3.67／3.75。缺省读取本页上次展示选择，再回退采购车选择和USD；这不是实时汇率服务，不改变真实价格、支付币种或结算规则。
- RULE-CHECKOUT-001：基准展示价格保持预结算API原值，单价按基准价格换算；行小计按基准价格乘数量换算，逐行四舍五入到展示币种的分，摘要为已显示小计之和。数量展示实际件数，另列商品款数。金额采用整数分计算并固定两位，75、28.11、60、24.40合计187.51，不暴露浮点尾数；单价与行小计可能因取整存在分的差异。
- RULE-CHECKOUT-002：币种变更只重绘商品金额和摘要，不发送预结算／地址写请求，不清除地址选择，不重新获取或覆盖商品数量。非法币种回退USD，存储不可用不阻止切换。
- RULE-CHECKOUT-003：采购车入口使用settlement_type=0；含sku_id与buy_num的立即购买入口使用1。确认按钮仍只传address_id、settlement_type和立即购买时的buy_count／sku_id，不传换算金额或币种；真实结算金额、运费和扣款币种以支付页为准。Q-010的正式多币种结算和全站币种一致性仍未在本次解决。
- RULE-CHECKOUT-004：地址为原API返回的本人可用地址，缺省第一条，可选择任意一条。新增地址通过现有API保存，保存后刷新预结算并选中新地址，保留币种；失败保留表单并提示错误。未加载成功、商品为空或无地址时禁止确认。

## 实现

页面 `orderConfirm.html` 不再带fixed_currency=True，不改动其他支付页面的固定币种模板。`orderConfirm.css`仅作用本页类名；`checkout-utils.js`处理分金额及参数，`orderconfirm.js`负责异步读取、DOM渲染、选择、弹窗和跳转。移除旧营销价标签、元符号硬编码及同步XHR；商品和地址字符串均作为文本渲染。

不新增／修改Migration，不更改orders、pays的金额处理、认证与资源范围。既有订单预结算按URL用户名读取等缺口不因本页改造而视为解决。未增加默认运费／税费或宣称外部支付支持USD／AED／SAR。

## 验收

1. 桌面三步进度不换行，图片与商品名对齐，摘要不被固定页头遮挡；窄屏有单列样式。
2. USD187.51切换后AED688.16、SAR703.16，切回USD仍187.51；单价、小计、币种表头和摘要同步。
3. 更换地址后切换币种，配送信息保持；新增地址后币种不丢失。
4. 空商品或无地址不能进入支付；立即购买参数不因页面显示币种变化而改写，浏览器验证不点击真实支付。

本次[证据](../../evidence/2026-10-18-checkout-confirmation/verification.md)使用隔离数据，不构成真实订单或支付验收。
