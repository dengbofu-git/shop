# 履约数据读取范围

2026-10-30：承接SDD提纯审查后，用户在“功能补全”明确确认以下允许/拒绝矩阵。规则针对现有物流和通用库存查询，不引入租户、商家仓库或新的权限代码。

| 身份 | 物流轨迹 | 通用库存/仓库 |
| --- | --- | --- |
| 匿名 | 401 | 401 |
| 停用账号 | 403 | 403 |
| 有效买家 | 仅本人订单；他人和不存在均404 | 403 |
| 有效商家 | 整单明细完整归属本店才允许；跨店、空明细、未知归属和历史混合单均404 | 403，即使单独获授inventory_manage；继续使用已有本店库存接口 |
| 有效平台角色 | 显式有效logistics_manage才允许；缺权限403 | 显式有效inventory_manage才允许 |

物流商家归属复用订单的购买时商家快照，缺失快照才回退商品当前归属。商品改归商家不能转移有快照订单的读取权。买家的历史混合订单仍属本人，可读物流；单个商家不能整单读取其他店铺物流信息。未授权与不存在返回一致，不泄露运单和轨迹。

每次请求重查账号、角色及权限，已有JWT不能绕过账号停用或撤权；平台角色优先按平台权限判断，不回退买家或商家身份以规避。物流响应禁止缓存。通用仓库属于平台共享配置；本规则不新增或推断“商家拥有某仓库”的关系。

实现涉及logistics.views、inventory.views；无数据库结构变化，无业务库迁移。源码及隔离数据验证不代表已重启服务或生产部署。
