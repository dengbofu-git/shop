# 推荐卡片加入采购车

2026-10-28，用户明确要求按“模型提供建议、用户发起操作、后端决定是否成功”设计并实施。关联总价推荐与CAP-TRD-001，具体实现模块为support_ai、goods、carts、web。

## 边界与交互

- Agent只推荐并返回公开商品卡片；推荐时过滤下架、非正价、无有效商家及无启用仓可售量的商品。有库存账本时以启用仓available_quantity为准，无账本才使用SKU.stock。
- 推荐后不会自动写采购车。普通卡片默认1件可编辑；套餐每行默认方案建议件数，可单独加入；整套加入使用当前展示方案，按钮标明总件数。详情链接与写按钮分开，卡片展示、切换方案和切换币种不写入。
- 加入只表示本人意向清单变化，不预留库存、不创建订单、不支付。后续下单继续执行交易系统校验。
- 历史推荐可点击但必须复核，删除的会话及不属于本人的推荐不能使用；没有可信请求引用的旧记录不显示写按钮。

## 用户操作契约

POST `/v1/carts/{username}/recommendations`，沿用用户JWT；活跃本人买家且路径账号一致。

```json
{
  "request_id": "本次用户操作UUID，重试保持不变",
  "recommendation_request_id": "本人已保存的推荐请求UUID",
  "bundle_id": "整套或套餐单行所属方案ID",
  "sku_id": 123,
  "count": 2
}
```

- 单品：sku_id必需、count默认1，可省略bundle_id。套餐单行带bundle_id及sku_id，count为用户可见输入值。
- 整套：只传两个请求UUID和bundle_id，不得传sku_id/count/items覆盖方案；后端从本人SupportTurn取得整套行及件数，最多4行。
- 只有后端生成的推荐引用可作为入口，不接受模型提供的数据库操作、Redis键名、价格或任意批量items。未知字段拒绝。
- 后端重新取得当前可售SKU、价格及库存，逐行核对已保存CNY报价；价格或价格口径变化返回409，要求重新获取推荐，不默默以新价加入。
- 不存在／不属于本人的记录或方案返回404；跨路径账号403；未登录401；字段错误400；变价、下架及库存不足409；基础设施失败503。

## 原子追加与重试

当前独立Redis服务使用Lua先检查所有行，再一次脚本执行内追加；累计件数为采购车已有件数加本次件数。某行库存不足或已有记录异常时不写任何行。Redis操作原子性不等于跨数据库事务：商品事实来自写入前复核，采购车不锁库存，下单必须再次校验。

成功回执按本人账号＋操作UUID保存24小时，并绑定规范化请求内容散列；同请求重试返回此前结果，不重复追加。相同UUID不同内容409。24小时后不是永久去重保证。价格或库存随后变化不影响已成功操作的回执查询。

旧单商品POST复用原子追加，并保留已有业务错误code处理；旧PUT和选择状态写入使用比较旧值再更新，避免覆盖并发追加的最新数量，冲突提示刷新。Redis故障不回退到非原子写入。整套并非订单级库存承诺。

见[本轮证据](../../evidence/2026-10-28-recommendation-cart/verification.md)。有效商家成为必要可售条件，相关合成测试夹具补充商家；0.25.1已变更的证据不足澄清行为同步到过期测试断言，技术依赖故障仍为503且不提交新轮次。

## 卡片回执与默认币种修正（web0.33.1）

加入成功后以接口carts_count（SKU种类数，沿用现有口径）同步当前页采购车图标和当前标签页缓存；身份切换时不将旧响应写入新账号，存储失败仍更新图标。采购车每次进入以CNY初始化，旧buyer_cart_currency不再覆盖默认值；手动切换只改变参考展示，不改后端人民币金额。
