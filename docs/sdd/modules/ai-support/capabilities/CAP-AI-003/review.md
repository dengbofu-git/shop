## 已复现的实现差异

### GAP-AI-003-01：英文格式原始订单引用进入模型输入

合成输入 `查询订单 order id: SDD-ORDER-B1` 或 `SDD-MISSING-X1` 的目标不属于当前买家。`current_order_context` 能识别它是不可见的明确订单，返回空订单 DTO；但 `redact(message, owned_ids)` 只额外替换本人订单号，通用正则主要识别中文订单标签或数字。再次经过 workflow 脱敏仍保留英文标签下的字母数字编号。

PROBE-03 观察应用边界，PROBE-08 捕获 mock 模型输入，两者均复现原始合成编号保留。**没有向真实外部模型发送这些数据**，也没有读取他人订单内容。差异对应 AC-03／07，说明“权限过滤成功”和“输入标识脱敏成功”需要分别验证。

建议设计增量：明确支持的订单引用语法，在应用边界提取并脱敏所有明确引用，不论是否属于本人；覆盖中英文标签、格式边界和否定案例。其他情况下的本人有效订单查询也需要该脱敏契约，不能只靠404分支掩盖缺口。

### GAP-AI-003-02：不可见的明确编号仍按成功聊天提交

当前 `current_order_context` 用空列表表达不可见的明确编号，和无订单等情况缺少可供 HTTP 层区分的显式结果。chat 仍进入受控任务图，mock 模型返回后得到 HTTP200，且外人／不存在两种输入各新增一条成功会话轮次。现在确认的目标契约为统一404、固定提示、无成功轮次。

建议设计增量：由应用读取结果表达“明确引用不可见”，在模型调用及成功会话提交前统一返回404；不需要区分目标属于他人还是不存在。未指定编号且本人无订单仍为正常空结果。这一变化需 API 与前端兼容评审，不在本轮直接修复。

### GAP-AI-003-03：旧历史响应尚未做读取脱敏投影

本次对账在合成旧轮次中保存英文形式的原始引用，再调用本人历史GET，HTTP200正文仍含该合成引用。当前conversation_detail直接返回保存的user_text/response，replay也直接返回旧response。新脱敏方案提出的读取投影尚未实现；不能用输入redact或预览safe_record替代这条HTTP路径的验证。对应AC-07／10，保留存量清理策略Q-013。
