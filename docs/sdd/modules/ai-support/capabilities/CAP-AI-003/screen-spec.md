## 2026-10-18 聊天输入快捷键增量

用户要求客服聊天输入框支持回车提交。本次仅实施现有输入框的快捷操作，不改变上述订单查询目标规格、接口契约或能力阶段：

- Enter 复用原发送按钮和表单校验；Shift+Enter 保留换行。
- 中文等输入法合成／选词期间的 Enter 不触发发送，兼容组合输入的 keyCode 229。
- 忙碌时不重复提交，按住 Enter 的重复键事件不触发新请求；空白仍由原提交处理拒绝。
- 输入框通过 aria-describedby 关联可见快捷键提示；静态脚本版本更新后刷新页面加载。
- 本次仅执行 JavaScript 语法、模块归属及 Diff 检查；未新增或运行交互测试，未做真实模型调用。

| UI-AI-003-13 UNAVAILABLE | 应用503；“暂时无法查询，请稍后重试” | 用户主动重试相同问题 → SUBMITTING | 保留完整pending和草稿，同一次重试使用原ID；不显示“没有订单” |

状态名是设计标识，不要求增加持久化状态表。200空结果／澄清使用 [API的应用结果定义](api-contract.yaml)，不按answer中文内容猜测。没有结构化依据的旧200答复按普通ANSWER展示，不谎报“已确认空结果”。

## 404、重试和恢复的关键区别

`ORDER_NOT_QUERYABLE` 是本轮问题的失败，不能清掉有效会话；`CONVERSATION_NOT_FOUND` 才清当前会话。GET历史接口404也按会话问题处理。旧服务端无error_code的chat404暂按原会话404语义兼容；目标服务端必须返回错误代码，不能靠文案包含“订单”判断。

同一问题在503／网络失败后重试，保留原始pending中的所有字段，包括当时revision；服务端若已提交则回放。若后续409，则刷新会话并等待用户重新发送，不能改revision却沿用原request_id。用户改消息、新查询或明确开始新对话时，结束原pending并生成新ID。

服务端明确404／503分支不会新增成功轮次；本地失败消息可以留在当前页，但不伪造服务器revision。网络或代理错误不能证明后端未提交。恢复记录以服务端成功轮次为准，失败气泡不写成已保存历史。

不实现自动无限重试或在页面离开时保证服务端取消。离开页面后请求是否已提交可能未知；同页面内存pending丢失后不冒充可进行精确重放，先恢复会话由用户确认再发新查询。

## 账号切换和并发界面保护

只把当前账号命名空间下的conversation_id／revision放sessionStorage，原始问题、编号、pending、回答和Token不新增到持久化浏览器存储。账号切换／登出时清当前客服内存；在途响应只能应用到发起它的账号和会话代次，过期回调不得显示到新账号页面。

输入中保留的原文仅在当前浏览器页面可见，发送前由服务端脱敏。模板展示使用textContent或等价安全文字渲染，不把answer／错误／历史当HTML插入。恢复记录批量渲染时不重复播报全部历史。

## 可访问性与响应布局

- 延续现有 `role=log` 和输入label；加载通过 `aria-busy` 与文字说明，完成后焦点回输入或可操作提示。
- 404、冲突和失败使用适当live-region提示一次，恢复时不要反复打断键盘或读屏用户。
- 键盘可触达发送、新对话、重试和“我的订单”，焦点可见；禁用控件同时给出原因，不能只变灰。
- 设计验证视口建议PC 1440×900和窄屏390×844；属于待评审测试目标，不宣称已支持所有设备或通过视觉验收。长状态、编号占位符和失败文案须换行不遮挡操作。
