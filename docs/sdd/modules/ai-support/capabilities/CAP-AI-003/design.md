# 订单工具和部分成功技术设计

设计0.2.0，目标规格0.3.0，2026-10-23。业务规则R01/R02/R09已确认，私有映射存储、兼容上线和技术评审仍待完成；本文件不证明已实施。

## 执行顺序

2026-10-28新增架构约束：[模型 Agent 数据访问统一经 MCP](../../../../architecture/agent-data-access.md)。0.24.0已使订单读取经 MCP 复用查询服务，并以签名私有通道交接 `OrderQueryContext` 的绑定效果；会话控制和最终提交仍属宿主职责，见[运行设计](../../mcp-runtime.md)。这不更改本 CAP 的业务选择、整体验收或技术评审状态。

1. 校验方法、有效买家、输入大小及字段；计算原请求指纹。本人同request_id成功／部分成功重放先返回确定性脱敏投影；内容冲突409。
2. 校验本人会话及revision；不可见会话404、冲突409，整轮不执行工具。读取允许的短期历史。
3. 本地提取并替换所有订单引用；明确语法按固定模板规划，复杂语义仅在必要时使用模型。模型不得设置owner、真实ID、SQL或工具名。
4. 根据计划按任务装配业务、知识、偏好依赖；普通订单不做偏好或模型服务前置检查。明确偏好任务才强制偏好读取。无法可靠解析复杂任务时明确不可用／澄清，不能猜测。
5. 订单工具在本人未隐藏范围内查询。纯订单明确不可见结果404，无成功轮次；混合任务将统一不可查询记入该步骤，依赖步骤跳过，独立步骤继续。敏感引用已替换，不向后续模型泄漏。
6. 工具仅返回公开DTO与安全错误；按api-contract聚合complete/partial和HTTP结果。计算金额和订单状态保持程序事实，不交给模型改算。
7. 完整响应投影检查PII／私有字段，再以MySQL短事务重查revision、幂等和必要归属；部分完成一轮提交，失败订单不设置active_order_id。最终冲突409，不重跑工具。

## 私有结果映射（R09）

最小内容为owner、conversation、query fingerprint、页面顺序到真实订单的映射、产生时间及页标识，全部留在应用授权范围。公开响应只含匿名位置、状态、日期、查询时间及分页控制。客户端或模型回传序号必须与服务端已展示页匹配。

当前页最多20项、24小时；翻页或新查询替换当前映射。输入“第二笔”先由映射选对象再查询实时状态；新订单插入不能让第二笔换人。隐藏、归属改变、过期及多候选按需求澄清或统一不可见。服务端需能在恢复本人咨询后安全恢复对应映射，缺失映射不能用模型历史猜。

存储位置、索引、敏感字段加密／权限和清理由技术评审确定；不把私有订单ID塞入公共response或模型上下文。若需新表／字段，另建迁移并在实际后端隔离库验证，不改历史迁移。

## 事务及回放

模型和工具外部调用在提交事务外；短事务按用户→会话顺序核查，部分结果和revision一次提交。完整／部分成功均可幂等重放，失败404／503不伪装成功；无结果／澄清可作为明确业务结果保存。安全读取投影不改历史业务结果，回放不延长或重排历史页，不自动刷新状态。

## 兼容及实施差异

URL、Bearer、原请求字段和已有响应字段保留，新增completion_status、warnings与任务错误字段，旧客户端仍能读answer；新客户端必须明确显示部分完成及可选偏好未用。先完成服务端兼容再启用新界面，旧版本回退须明确新规则不再满足。

当前已有只读订单工具、签名游标、日期筛选和部分错误码；0.24.0完成 MCP 访问、任务偏好依赖及不可查询订单与独立推荐的部分完成回归。服务端序号映射、全部投影／界面兼容及Q-011/Q-013的新版本AC证据仍未齐备，不记录整项技术验收或发布批准。
