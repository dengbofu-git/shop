# 订单查询、结果映射与脱敏边界

规格0.3.0，2026-10-23。业务目标最小化与只读边界保持；本文件为待技术验证的出入站要求。

| 数据 | 应用私有 | 模型／公共响应 |
| --- | --- | --- |
| 用户身份、真实订单号、收件／联系信息、凭据 | 仅认证、本人过滤及授权提交需要时使用 | 禁止 |
| 订单结果位置映射 | 绑定当前本人会话及已展示页，最多20项、24小时 | 只能看到匿名位置标签，不能作为绕过鉴权的能力令牌 |
| 订单公开事实 | 从交易域实时读取 | 只给必要匿名reference、order_status、payment_status、shipping_status、created_date和queried_at；未知明确标unknown |
| 请求／会话ID和revision | 幂等及会话控制 | 仅本人客户端控制字段，不进入模型提示词 |
| 历史轮次 | 本人会话读取 | 再脱敏；模型最多24小时／6轮／6000字符，临时引用不提供数据库主键 |
| 错误、trace及工具状态 | 安全诊断 | 允许错误码、任务状态、公开trace_id；不带异常正文、SQL或原始编号 |

引用识别先于一般PII过滤：完整匹配中英文订单标签及合法候选，不能截断长值再查前缀；多编号或不明确格式先澄清。本人过滤不依赖枚举全库编号，明确不可见一律相同提示，不做全局存在性查询。请求内随机ORDER_REF映射只帮助工具定位，禁止输出原始映射。

本轮问题、历史、计划、知识查询、组合表达、诊断和所有响应文本都在边界检查；过滤已知标识与PII，禁止把模型对象字典直接序列化。有限正则不能保证识别所有自由文本个人信息，必须用合成正反例和目标语种验证。

混合请求中不可查询订单只以not_queryable和统一文案表达；其他独立任务不接收原始编号，模型不得因此推断订单存在。成功／部分成功、历史GET及request_id重放使用同一确定性公开投影；只清除敏感信息，不刷新价格、状态或改历史记录。失败任务不能写成成功订单事实。

日志／OTel采用运行字段白名单，不保存输入输出、候选编号、私有映射、地址、Token、URL查询或完整异常。CLI脱敏JSONL属于另一个本地记录类别，须独立访问／保留策略；窗口24小时和浏览器隐藏都不代表数据删除。

验收需捕获真正发往模型、HTTP、会话及遥测的完整树，覆盖本人／他人／不存在编号、混合失败、英文引用、凭据、旧历史／回放及序号篡改。本轮未执行泄漏探针；Q-013保留周期与清理仍待确认。
