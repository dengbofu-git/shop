# 当前买家 Agent 能力与数据边界

2026-10-19 语义规划增量对账；实现模块为 support_ai 0.12.0、ai_storage 0.3.2。本次没有页面改动。版本表示当前工作区登记，不代表发布。本文记录已实现行为与待验收点；CAP-AI-003 的规格0.2.0和 SPEC_REVIEW 状态保持不变。

## 任务和工具

`workflow.py` 按脱敏、规则或统一语义规划、服务端计划、执行、组合、安全检查和输出组织一轮对话。`semantic_planning.py` 同时判断本轮动作、解析指代、提取复杂任务及购买条件，并保存结构化待补充状态，详见 [语义规划与任务状态](../../../Agent语义规划与任务状态.md)。`planning.py` 接受原六类业务意图及greeting、system_help两类固定回复，最多5步；工具不能生成任意下一步、SQL或代码。`execution.py` 按依赖派发，90秒是派发预算，不是强制中断全部在途调用的硬超时。

| 意图 | 固定工具 | 行为与边界 |
| --- | --- | --- |
| recommendation | recommend_products | 校验原话／历史／显式软偏好证据后筛选商品；单组1—4款，分组最多6类、每类最多4款、总计最多12款 |
| recommendation_explanation | explain_recommendations | 解释原列表中明确选定商品，重读当前事实，不自动换成新商品；歧义或不可售时明确说明 |
| question_answering | introduce_tea | 基于已发布且用户可见的知识作答；茶类说明仅在有验证证据的范围内关联推荐 |
| product_details | get_product_details | 先解析当前结果或历史商品指代，再经共用公开详情服务重查；缺货／下架不补其他商品 |
| after_sales | get_order_status | 应用按本人身份准备订单DTO，工具解释现有状态；不能退款、发货或推进订单 |
| clarification | ask_clarification | 询问缺失对象或条件，不将系统错误一概解释成用户信息不全 |
| greeting / system_help | greet_user / describe_capabilities | 精确规则匹配后返回固定问候或功能说明 |

独立任务可在其他步骤失败后继续，依赖非success的后续步骤跳过；全部工具error／skipped时HTTP503，不提交成功轮次。部分成功通过 tasks 和 unmet_requirements 反映，不能以HTTP200代表所有子任务完成。

## 商品事实和公开详情

推荐条件分 required、preferred、excluded，明确条件要求原文证据；已保存偏好只能作为软条件，服务器核对其来源。推荐理由依赖实际商品字段，不根据茶类推断认证、功效或个人适用性。

当前网站商品详情工具与本地 MCP 共用 `support_ai/product_details.py`。只返回已上架且正可用库存SKU，账本存在时取可用量合计，仅无账本时回退SKU.stock。成本和商家身份不在SQL公开投影中；可见属性使用白名单并限制条数。USD延续既有Agent展示约定，不是数据库已记录币种或支付币种承诺。

MCP get_product_details 是开发者本地stdio工具，不是HTTP公开接口或站内身份认证替代品。独立Python3.12 SDK通过固定Django命令查询，未写会话、足迹或偏好。调用、错误和输出说明见 [接入说明](../../../MCP与Skill接入.md)。[search_products](search-products-design.md)仍为设计草案，没有可调用工具。

## 检索与长期偏好

知识链路包括受控查询翻译／扩展、最多4条首轮查询、多查询融合、去重、可选重排、证据与来源预算，以及最多一次补检。入库和查询必须属于同一向量空间；文档可见范围由服务端限定，不由模型提供owner决定。

长期偏好由本人显式GET／PUT／DELETE维护，保存在AI PostgreSQL；分类、品牌、关键词各最多5项，每项最多40字。查询条件有独立上限，不能把偏好上限套到六类推荐。收藏、足迹、模型回复和商品点击不会自动变成长期购买条件。页面默认展开偏好设置，不改变保存语义。

RAG改写能执行不代表检索质量提升。0.9.0真实对照发现重排查询拼接及来源限额造成证据损失；0.10.0追问修复也不代表该问题已解决。模型服务、重排序ready状态和历史实测数值均不能当作当前运行状态。

## 会话和历史

当前 chat 接受 message、conversation_id、request_id、expected_revision；应用先检查成功重放，再读取本人会话、短期上下文和偏好。使用现有请求哈希和revision处理重复／冲突，数据库提交成功不意味着外部模型调用可撤回。

历史咨询提供本人列表和sequence分页，详见 [历史咨询规格](conversation-history.md)。新页面每次20项／20轮，接口上限50；旧详情请求无参数时仍默认6轮。展示旧记录不扩大模型窗口：仍为所选会话最近24小时、最多6轮、6000字符。

0.12.0新增turn_action及dialogue_state；当前任务、条件证据、缺项、数量和分组方式与轮次JSON原子提交。补充／修改合并已有条件，新请求重新建立筛选条件，取消清空状态；窗口之外的原话依据不再继续使用。旧轮次无状态时按idle处理，不再根据助手文字猜测待补充购买任务。0.12.3已补充隔离回归和真实模型合成验证，见[本轮证据](../../evidence/2026-10-19-regression-repair/verification.md)，不沿用旧评测成绩证明新链路。

列表／详情会校验活跃买家并再次脱敏字符串；chat／preferences的共享认证还未额外检查is_active。历史GET不刷新价格、库存或订单状态；已保存成功replay也不实时重查，且尚未接入同等读取脱敏投影。英文编号、临时ctx引用、错误码和订单不可见404等目标差异见 CAP-AI-003 的观察契约。

页面支持Enter发送、Shift+Enter换行、输入法选词不发送和忙碌去重。商品卡片优先显示product_name，name为规格补充，新消息与恢复历史共用；当前仍为扁平卡片渲染，不声称具备完整分组专用组件。旧会话、草稿、账号变化和恢复失败的预期行为见历史咨询与页面状态规格。

## 开发和运营

`agent_preview` 是本地开发命令，默认不写客户轮次／运营遥测；指定活跃买家后才消费其私有事实，脱敏JSONL属于本地文本记录，不等同HTTP遥测无内容策略。运营配置每次请求取快照，配置revision与模块版本不同。平台权限、知识库占位及监控见 [Agent运营规格](../platform/agent-administration.md)。

## 验证与缺口

初始对账只作源码和SDD静态检查。公开详情与MCP的历史验证见 [MCP证据](../../evidence/2026-10-18-mcp-skill/verification.md)。0.12.3重新验证既有回归，修正模型协议、页面入口与错误契约的测试预期，补足偏好和确定性规则；当前结果以[本轮证据](../../evidence/2026-10-19-regression-repair/verification.md)为准。历史咨询和快捷键仍缺完整浏览器端到端证据。0.10.0的15组41轮统计仅代表历史限定样本。
