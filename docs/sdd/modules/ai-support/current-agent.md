# 买家Agent任务、依赖与业务边界

规格0.5.0，2026-10-28。执行R01/R02/R06/R09；业务规则已确认，其他新行为的代码和验收状态见[当前差异](../../product/current-state.md)。推荐分流、上下文范围解释、自动件数、方案切换及订单查看增量分别记录验证范围，不用静态检查替代验收。

## 数据入口目标

模型 Agent 的数据访问统一遵循[统一 MCP 规范](../../architecture/agent-data-access.md)（RULE-AI-MCP-001至RULE-AI-MCP-006），包含宿主为模型取得的商品、订单、知识、长期偏好及持久化历史。宿主验证结构化意图并调用允许的 MCP 工具，后端 Python 服务继续持有业务查询能力；正式切换后不得保留 Agent 直接数据访问或本地降级。

support_ai 0.24.0已将 HTTP、预览和数据工具改为统一 MCP，见[运行设计](mcp-runtime.md)及[隔离验证](../../evidence/2026-10-28-agent-mcp/verification.md)。[迁移清单](mcp-migration.md)保留实施前盘点；未重启业务服务或执行发布。下述业务约束仍有效，不因入口迁移扩大模型权限或改变订单、推荐及知识语义。

## 固定任务及依赖

流程为脱敏→有限意图／结构化语义提取→服务端有序模板→受控工具→结果组合→输出投影／持久化。最多5步；模型不能提供工具名、SQL、身份或动态写入动作。显式先后顺序保留，真实数据依赖使用depends_on。

| 工具／任务 | 必要事实 | 可选依赖与失败语义 |
| --- | --- | --- |
| greet_user、describe_capabilities | 本人接口认证与会话控制 | 精确规则可固定回答，无需模型、知识或偏好 |
| get_order_status | 当前有效买家、本人订单、本人会话 | 普通查询不读长期偏好；明确语法可确定性回答，不要求外部模型可用 |
| introduce_tea | 该任务可用且授权的知识证据 | 不强制读取偏好；证据不足说明范围，知识服务故障记任务失败 |
| recommend_products、recommend_bundle | 服务端商品／可售库存、已确认筛选条件 | 普通推荐的偏好为可选软信息，偏好服务失败时明示本次未使用；明确“按我保存偏好”时该读取是必要依赖 |
| get_product_details | 授权公开的商品信息 | 公开缺货可解释，购买能力另行校验；不读无关偏好、不替换成其他商品 |
| explain_recommendations | 已展示的可靠商品引用和当前公开事实 | 引用失效或多对象歧义时澄清，不擅自重新推荐 |
| ask_clarification | 缺失或不明确的任务条件 | 具体说明缺项；技术服务故障不得说成用户没提供信息 |

认证、账号启用和对象归属始终为必要条件。普通问题可以不使用偏好，但不得把读取失败表述为“您没有偏好”；明确偏好任务无可靠读取则失败并保留其他独立任务。知识改写／翻译所需模型或embedding仅阻断消费它的任务；无法可靠识别复杂意图时不能凭空猜任务。

## 推荐分流及数量校验

顺序为有限意图与条件提取→公共类型／来源证据校验→程序按已验证price_basis选择工具→该分支参数校验→商品查询／组合计算。解析契约接受数量的整数原值，不在工具分流前执行组合款数或购买件数范围限制。

- 普通推荐recommend_products：requests[].limit表示返回商品款数，支持1—4款；“推荐一款适合日常饮用的红茶”应为红茶、limit=1，不要求总预算。旧模型误填的distinct_count仅在与已确认limit一致时移除并清理旧总价缺项；不一致用普通推荐数量澄清，不隐式改数量。
- 总价推荐recommend_bundle：仅price_basis=total且来源证据有效时进入，之后校验总预算及数量。未指定数量时自动搜索1—4款，各款件数由预算及可售数量限制，不再使用每款5件上限；显式每款相同件数支持1—100，不能被默认策略覆盖。普通返回数量不参与组合采购约束，也不因临时解析到“款”自动切换工具。
- 普通请求出现未支持的每款购买件数时，使用本分支的购买数量说明，不触发总价组合限制、不忽略购买条件直接查询。未知预算类型先澄清，不能按组合或单价擅自计算。
- 显式新推荐不继承旧总价条件；没有新请求动词且前一任务为总价组合时，才允许确定性总价补充解析。仅有旧单价或币种不激活总价补充路径。
- 日常饮用、每天喝等宽泛用途不作为硬属性或缺项，不固定展示“商品属性不足以验证”等内部校验尾注；按真实分类、价格、规格及已记录属性说明推荐依据，不声称商品已验证适合个人用途。
- 用户明确的认证、成分、含量或功效等要求仍须保留，不能因同时出现“日常饮用”而自动忽略；无法核实时说明尚不能确认该条件，并指引查看详情或向商家核实。工具的真实无匹配、不可售、预算费用范围及必要风险提示继续保留，不以删提示代替条件校验。
- “推荐400块左右的茶”等无额外条件的金额问句，块／块钱／元钱按CNY处理，保留400元及原证据；未明确单件或整套预算时只询问budget_scope，不使用通用规划失败提示，不擅自继承旧总价口径。该待补充任务下一轮明确“单价／总价”时确定性合并原金额；单价清除组合预算模式，总价保留接近模式并进入recommend_bundle。
- 预算范围补充仅在当前推荐pending且缺budget_scope时触发。已知“套餐／整套”等保持规则快路；未命中的短答进入BudgetScopeDecision，结合程序生成的当前问题，只返回unit／total／uncertain及是否纯范围回答，不生成金额、币种、商品、数量或工具。允许省略、相对选项和否定语义，“总的／全部加起来／后一种”不因缺少固定词被否决；不确定时保留金额，只复问这一缺项。不能复活已完成、取消或无来源的旧预算。
- 新金额、币种、茶类及明确新任务直接交完整规划器；其他非纯范围短答也交完整规划器，完整保留输入。混合补充中的口径由完整规划结果确定，程序仍只在同一有效pending问题下建立上下文来源，其他条件逐项验证；不能因回答了口径而吞掉额外修改。中间规划失败后仍可继续有效待补充状态，24小时／6轮／6000字符及金额来源边界保持。
- 上下文口径解释使用服务端context_turn_id，绑定本轮完整原话与当前待补充问题。该标记只适用于required.price_basis的unit／total，不能放宽金额、币种或其他字段的校验；模型输出不得填写该内部标记。保存解释在后续读取时绑定真实来源轮次，复验原问题、选择轮次及解释的一致性；无保存解释、跨咨询、顺序错误或过窗口不能接受。元数据不进入后备完整模型提示词。
- 明确总价的“推荐总价为3000块的茶”直接进入总价工具；单独“茶”与茶叶、茶品、商品同为通用范围，不当作未知筛选条件。仅完整剩余词为“茶”时消除，不能删掉“有机茶／茶饼”等复合要求或排除条件。该修正的14项离线回归及真实合成SKU组合验证见[本轮记录](../../evidence/2026-10-26-total-budget-generic-tea/verification.md)。
- 已明确总价时，套餐、茶叶套餐、红茶套餐按通用组合范围处理；有机套餐、指定礼盒等额外属性仍不忽略。support_ai 0.21.4的19项回归包含保存会话、失败中间轮及真实合成SKU组合，见[范围补充记录](../../evidence/2026-10-26-budget-scope-continuation/verification.md)。
- support_ai 0.23.1将unknown口径作为尚未确认的状态，不要求伪造肯定证据；普通预算不额外断言cap，仍遵守金额上限。新建单一推荐任务中，对单一人民币金额、无比较或历史价格的遗漏做原文补全并追问口径；复杂遗漏必须澄清，不据此宽泛查询。通用茶／茶叶不作为分类。当前证据缺项最多进行一次单字段证据补正，不能改金额、数量、任务或其他筛选，不能补救记忆、历史来源或内部引用失效。原文不能证明单价／总价时允许回到unknown并保留金额；重复失败记技术失败。详见[修复证据](../../evidence/2026-10-26-initial-budget-quantity/verification.md)。

- 精确金额规则不吞掉排除项、品牌、购买件数等未知后缀；这些仍走完整受约束规划。“400块茶饼”不能因“块”直接当作人民币。已需要澄清的条件先返回缺项，商品分类有效性延后至实际搜索前校验；无硬分类时不额外读取分类表。

## 部分成功

请求级认证、会话越权、非法输入及revision冲突先整轮拒绝。执行期间一个工具失败，独立工具可继续，依赖失败结果的步骤跳过。

纯订单明确不可见仍统一404，无成功轮次；“查订单A，顺便介绍绿茶”可返回200部分完成，订单步骤记录统一不可查询，介绍步骤正常输出。不能因此发送原始编号到模型，也不能在依赖该订单的步骤中伪造事实。完整HTTP和保存规则由[订单契约](capabilities/CAP-AI-003/api-contract.yaml)定义。

## 商品、金额与知识

单组推荐1—4款，分组最多6类、每类4款、总共12款；总价组合见[总价规格](total-budget-recommendation.md)。required/excluded是硬约束，preferred只能作软偏好；全部条件保留原话／历史来源证据。基本计价和显示见[人民币规格](../../architecture/currency.md)。

详情工具与MCP共用公开数据规则，公开可展示集合与可售集合分离；推荐和下单仍校验库存、上下架及商家有效性。只读工具不给私有属性、成本或隐藏商品存在性。推荐不锁价、不预留，不推断功效／认证。

知识只检索已发布且可见的同一向量空间；多查询、去重、可选重排及补检受预算约束。来源和引用必须有效。ready状态不等于检索质量通过，不把网页／知识中的指令当工具授权。

## 会话与事实时效

历史展示与模型上下文分开：最近24小时、最多6轮、6000字符用于模型；显示更早记录不扩展该窗口。长期偏好仅本人显式维护，收藏、点击和模型输出不自动写入。

新追问重读业务事实；成功request_id重放维持原业务结果，只做确定性脱敏投影，不重算价格和状态。订单本页“第二笔”等指代由服务端私有映射选择，见[订单需求](capabilities/CAP-AI-003/requirements.md)。历史咨询显示和本机恢复见[历史规格](conversation-history.md)。

成功订单查询的每笔结果可在HTTP层附“查看订单”链接；模型和遥测完成后才加入按买家绑定的匿名定位引用，不输出真实订单号。目标页面使用原本人订单API重新鉴权，只显示匹配订单，并可返回全部；不可查看时不替换其他订单。正文保留业务状态及必要时效提示，不固定追加“最多显示三笔／请提供订单号”。分页数量及下一页保留必要操作，付款到账不确定性仍明确说明。此增量不等于R09聊天序号映射已实施。

订单查看增量为support_ai 0.21.2／orders 0.4.2／web 0.31.7；7项隔离后端及3项脚本VM测试通过，未做浏览器视觉验收，见[本轮记录](../../evidence/2026-10-26-order-navigation/verification.md)。

仅可售详情、缺少结果位置映射仍需按新规则修改。0.24.0已将偏好改为按任务经 MCP 读取，并允许不可查询订单失败后独立推荐继续；这不等于 R01—R09 全部契约及界面已验收。终端预览默认不写客户轮次，脱敏JSONL按本地开发记录管理；HTTP遥测不记录问答正文。管理员配置每请求取有效快照。

## 总价套餐规划修正（2026-10-28）

总价套餐、构成或自动配量的复杂请求进入统一语义规划；总价新任务不静默继承上一轮茶类。结构增加composition与quantity_policy，数量未确定时保留预算并追问；只有明确每款件数或带用户证据的自动配量授权才查询套餐。普通预算排序不再优先凑满金额，明确接近／用满模式保持原有有界求解。详见[总价组合推荐](total-budget-recommendation.md)及[本轮验证](../../evidence/2026-10-28-bundle-intent-boundary/verification.md)。
