# 买家客服流式反馈

实施日期：2026-10-29。support_ai 0.27.0、web 0.33.0、core 0.10.1。依据：用户要求“将助手的回答全部修改为流式传输，能更快一点得到反馈”。本次覆盖已接入的买家网页客服；商家助手已退役，不在本次范围内。终端预览和机器客户端仍保留完整结构化结果格式。

## 数据交接与协议

浏览器通过带 Bearer 身份的 `POST /v1/support/chat/`，使用 `Accept: text/event-stream` 选择 SSE；没有该 Accept 的旧客户端继续接收原 JSON。请求字段、权限、所属会话、revision、request_id 和请求摘要规则不变。不会自动重连并重复提交 POST。

认证、请求格式等前置失败仍用真实 HTTP 400/401/403/413 等 JSON 错误；流式容量已满返回 HTTP 503。流开始后无法改 HTTP 状态，业务错误通过 `error.status` 表达；页面将 404/409/503 等接回原有恢复逻辑。

| event | data | 产生条件及页面行为 |
| --- | --- | --- |
| status | stage、message | 先发送 accepted，再启动工作线程。后续为历史、偏好、理解、规划、检索、生成、核验、商品匹配、订单查询、保存等实际阶段。文本为服务端白名单 |
| answer | text、provisional | 完整的当前文本快照，页面替换文本。true 表示任务结果已核验但本轮尚未保存；false 为提交成功后的权威文本 |
| ping | elapsed_seconds | 后台没有新事件时约每5秒保活，不宣称工具已完成，不增加查询或模型调用 |
| done | 原 chat 完整响应 | 仅在 commit_turn 成功或合法幂等重放后产生。页面更新 conversation_id/revision，展示来源、商品卡片、订单链接，标记咨询已保存 |
| error | error、error_code（可选）、retryable（可选）、status | 整轮错误终止，不发送 done。页面移除临时回答并显示错误，解除提交锁定 |

响应头为 `text/event-stream; charset=utf-8`、`Cache-Control: no-store, no-transform`、`X-Accel-Buffering: no`。经过反向代理时，该路由还需确保代理不缓冲，不能仅凭模型接口开启 stream 就认定浏览器已经流式。

## 输出约束与实际延迟

模型接口开启 `streaming=True` 及 `stream_options.include_usage`，结构化工具调用片段仍由 LangChain 聚合，再按既有 schema、来源与证据规则校验。未核验草稿、部分 JSON、思考内容及工具参数不发送给买家。

执行器在每项工具完成后，复用 `business_grounding.needs_model_review` 判断该结果是否可独立发布：程序产生的订单／商品事实、固定答复、已完成独立证据核验的知识单元可发送；需要审核的内容继续等待原有审核。发布复用原答案渲染和脱敏函数，按 output_order 组合文本快照。知识拒绝与核验失败的原有行为不放宽。

此处是**进度和已核验任务结果的流式传输**。一个知识任务仍须完成召回、重排、生成和复核，不能在模型刚生成未经核验的首字时展示。只有一个任务时，回答正文可能作为一个已核验单元到达；多任务可以在剩余任务处理时展示先完成的结果。不做逐字延时动画，不增加打字效果的 sleep。首个进度更早到达不代表重排或模型总耗时已缩短。

## 状态、并发和资源

网页状态为：提交 → 处理进度 → 可选的已核验临时结果 → 保存 → done；或进入 error／连接中断。done 是保存成功的唯一标记；先前 answer 不代表数据库已保存。

每个 Web 进程最多8个流式执行线程，事件队列最多32条。队列拥堵时允许丢弃中间进度或旧文本快照，最终响应单独保存，不因队列满而丢失。每轮复制独立 ContextVar 上下文，模型预算、MCP grant、权限和 Trace 不跨请求共享。线程退出关闭其数据库连接并释放容量。

客户端关闭／换账号／离开页面会取消读取。后台在阶段、工具与保存前检查取消；本进程模型流还在 Token 回调检查。已经发出的阻塞 MCP／HTTP 请求仍受原有超时约束，不能即时撤销远端调用；已进入提交的事务也不承诺回滚。请求可能已保存但 done 丢失时，网页保留原 request_id，手动重试通过既有幂等重放找回，不新增一轮。409 则读取会话最新状态后重新提交。

页面按 UTF-8 字节流解码，支持拆开的码点、CRLF、事件边界及一批多个事件；缺失 done 的 EOF、非法 JSON、过大消息均按未确认结果处理。每次网络 await 与每个事件前核对账号，身份变化先取消连接、清空旧内容并锁定页面等待刷新。answer 始终通过 textContent 显示。

## 日志与兼容

HTTP 完成日志延迟至流迭代结束或关闭时记录，合并后台线程的 Trace；duration_ms 包含响应流生命周期。流已经发 HTTP 200 后失败时，http_status 仍为200，business_code 保存实际业务状态，outcome 按业务状态判定。日志不保存回答、输入、SSE data 或密钥。

固定欢迎／功能介绍也通过同一流协议发送，仍不读取长期偏好、调用模型或启动 MCP。MCP 数据访问边界不变；没有数据库迁移。当前验收覆盖 WSGI LiveServer 与 Edge 浏览器，未验证其他 ASGI 部署及线上反向代理。
