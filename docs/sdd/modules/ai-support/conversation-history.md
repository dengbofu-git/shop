# 买家客服历史咨询

规格增量 0.1.0，2026-10-18。用户在确认历史入口价值后明确要求实施。对应现有 `buyer_support.html` 和本人客服会话；本增量不提升 CAP-AI-003 订单查询草案的生命周期状态。

## 交互规则

- 聊天区顶部提供“历史咨询”次级按钮，展开本人咨询列表；按最近更新时间降序显示，包含首条用户消息生成的简短标题、更新时间和轮数。
- 列表每次读取20项，可加载更多；标题由已保存、再次脱敏的首条用户消息截取产生，不调用模型生成。
- 选择咨询读取最新20轮，按原顺序展示；“加载更早记录”向前分页，每次20轮。已保存记录的展示不受模型24小时、6轮预算限制。
- 当前咨询名称可见，列表标记当前选中项；旧答复显示记录时间及价格、库存和状态可能已变化的提示。
- “新对话”清空当前聊天引用，首次成功发送后才创建数据库会话；旧会话继续出现在列表。切换旧会话后，后续发送携带该会话ID及本次读取的revision。
- 切换已保存会话时，未发送草稿和待重试请求只在本页内存中按会话保存，返回时恢复；不把消息草稿写入浏览器持久化存储。“新对话”主动清空新咨询草稿，刷新页面不恢复草稿。
- 提交、恢复、列表加载或记录分页时，暂时禁止发送和切换；列表／详情失败可重试，切换失败保留当前咨询。初始恢复或409后恢复失败，阻止发送，用户可从历史列表重新打开或明确新建咨询。
- 新旧回复仍复用当前商品卡片与引用资料渲染。历史卡片价格是记录值；详情链接查询当前商品，用户继续追问时沿用现有实时业务工具。
- 当前标签页账号变化后清除已渲染旧会话、草稿和偏好；异步结果在读入及应用前核对身份，刷新页面后重新使用当前身份。

## 只读接口

所有接口使用现有 Bearer 买家鉴权，拒绝停用账号；每个查询按当前买家过滤，数据库异常返回503，响应设置 `Cache-Control: no-store`。

### `GET /v1/support/conversations/?limit=20&cursor=...`

- 默认20项，上限50项；`cursor`为绑定当前用户的签名游标，携带更新时间和会话ID排序位置，有效期24小时。游标过期只要求刷新列表，不删除记录。
- 返回 `conversations`、`has_more`、`next_cursor`；每项包含 `conversation_id/title/created_at/updated_at/turn_count`。
- 不列出没有已保存轮次的空会话，不返回订单引用、账号信息或模型配置。列表加载不读取偏好库、不调用模型。
- 重复参数、未知参数、非法limit或游标返回400。

### `GET /v1/support/conversations/<uuid>/?limit=20&before_sequence=...`

- 无分页参数的旧客户端仍默认读取最近6轮，保留原 `conversation_id/revision/turns` 字段。
- 新页面显式请求20轮，上限50；按不可变的 `sequence` 向前读取，不用页码偏移。返回的每页 `turns` 按旧到新排列。
- 新增 `title/turn_count/created_at/updated_at/has_more/next_before_sequence`；每轮新增 `sequence/created_at`，保留 `message/response` 并再次执行既有脱敏规则。
- 不存在和他人会话统一404。合法本人会话的无结果页返回空数组，分页参数无效返回400。
- 加载旧页不更新页面当前revision；其他标签页已经追加消息时，下次发送继续触发原有409刷新流程，避免把未显示的新消息视为已读。

## 数据与上下文边界

使用现有 MySQL 会话、轮次和序号，无数据库迁移；不新增历史删除、保留期、清理任务或批量导出功能。旧数据保留策略沿用现状，本次不承诺永久存储。

历史分页只影响展示。模型仍从当前所选会话取最近24小时、最多6轮及原字符预算；长期偏好继续由用户主动维护。旧会话超出该窗口时，继续提问应补充需要沿用的对象与条件，历史不会自动成为长期记忆。

## 预期验收点

1. 新建后原咨询仍可从列表找回；切换旧咨询后发送绑定正确ID及revision。
2. 多于20项的列表和多于20轮的会话可逐批加载，保持顺序；显示历史不扩大模型上下文。
3. 他人ID、非买家、停用账号和无身份访问被拒绝；游标不能跨账号使用。
4. 切换失败不清空当前聊天；草稿在本页会话之间保存；发送中不能切换；账号变化后不应用旧请求结果。
5. 历史答复带时间和状态变化提示；加载更早记录后保持滚动位置。
