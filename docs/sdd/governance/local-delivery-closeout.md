# Git 交付的本地收尾设计

版本：0.1.1。更新：2026-10-28。状态：来源记录、收尾模式及恢复入口已接入交付 Skill；自动核销／回收工具尚未实现，本次未执行本地清理。

依据：用户要求设计本地收尾并写入 SDD；[根协作规则](../../../AGENTS.md)、[Git 协作规范](../../Git协作规范.md)、[SDD 工作约定](workflow.md)。本文细化现有现场保护和收尾要求，不扩大提交、分支切换、合入、删除远端分支或部署授权，不新增产品能力或业务阶段。

## 问题与目标

远端 PR 合入、原工作区中的改动核销、临时工作区回收是三件不同的事。现有流程明确要求保护工作，但缺少交付前后的对应清单和恢复入口，导致独立交付区已合入后，原工作区仍停在旧 HEAD，旧的未提交副本不断被当作新工作。

特别是，文件与 main 内容相同，不代表 `git status` 会自动干净：Git 比较的是该工作区的 HEAD、暂存区和工作文件。删除这份文件或只把 main 内容再写一遍，都不能正确解决旧 HEAD 与脏现场的问题。

目标是每次都能回答：哪些改动已交付、哪些仍未交付、哪份工作区可回收、哪些保留及原因。已交付副本不再进入下一次 MR；真实未交付工作、暂存意图和运行数据得到保留。用户仅要求推送／建 PR 时，完成该请求即可返回，不等待未授权的远端合入。

## 完成口径与状态

不使用一个“已完成”字段混合所有事实。每份交付记录至少包含以下维度，与产品能力的四种 assessment 状态独立。

| 维度 | 状态 | 判定 |
| --- | --- | --- |
| remote | not-pushed / pushed / pr-open / merged / closed-unmerged / unknown | 远端实际结果；关闭 PR 不等于合入 |
| original | not-needed / pending / reconciled / residual-preserved / blocked | 原始工作是否已核销，仅剩明确归属的未交付增量 |
| temporary | not-needed / pending / recycled / retained-policy / blocked | 本次管理的临时工作区和本地分支分别记录实际结果 |
| closeout | waiting-merge / ready / in-progress / blocked / complete | 本次收尾计划的整体状态 |

- 推送与建 PR 成功时，报告“请求已完成，远端待合入，本地收尾 waiting-merge”，不声称全部收尾完成，不删除未合入产出。
- remote=merged 只解除“尚未合入”这一项条件，不能直接把其他维度改成完成。
- closeout=complete 要求：合入已核实；原工作核销已完成或确实不适用；剩余工作已明确归属；计划中的临时资源已回收或按明确保留策略登记；无未知归属、未经处理的已交付副本或待确认的占用。
- retained-policy 必须写明保留对象、用途、负责人或所属任务、下次检查条件，例如继续开发的长期分支。仅写“为了安全保留”不能代替核销；等待授权、占用未知或回收失败应记 blocked。

## RULE-LCO-001：先减少重复现场

同一目标优先复用原开发分支和已有适用工作区，不按聊天轮次建工作区。原工作区适合精确提交时，直接提交授权增量，使该部分自然从未提交状态消失。

确需保护混合脏现场或真实并发时，才建立独立交付区，并登记 `branch.<分支>.teaSaasOwnerBranch`。独立交付区只应用授权增量；完整现场备份属于恢复材料，不能把其他任务的副本都变成该交付区的开发改动。先识别已在最新 main 的内容，避免重复交付。

## RULE-LCO-002：建立可追溯交付记录

在隔离交付前记录来源，而不是合入后凭记忆猜测。最小记录：

| 信息 | 最小内容 |
| --- | --- |
| 身份与授权 | delivery_id、任务、仓库、授权动作和范围；本次创建／复用的工作区及分支、回收目标 |
| 原现场 | 原 HEAD、暂存区快照、未暂存差异、未跟踪文件；相关文件类型、mode、原始字节哈希；必要的忽略文件和运行依赖清单 |
| 交付范围 | 路径或明确 hunk／增量、基线对象、实际交付后的对象与补丁哈希、所属模块；不能只有文件名 |
| 远端对应 | 分支、源 SHA、main SHA、PR、合入方式、合入后 SHA 与时间 |
| 收尾计划 | 原工作核销方法、待保留增量、各资源所有权／占用检查、回收前提和恢复位置 |
| 实际结果 | 各维度状态、执行前后指纹、命令和结果、保留／阻塞原因及下一步 |

本机恢复材料放在持久主工作区的 `.scratch/git-delivery/<delivery_id>/` 或明确指定的持久目录，不放在将被删除的临时工作区内。暂存与未暂存分别保留，不能仅保存合并后的最终文件。材料不可覆盖已有记录；若需要写入秘密或运行数据，保持本机私有并按实际用途保护。

需要共享时，把脱敏结论和源码／日志指纹写入 `docs/sdd/evidence/<run-id>/`。不提交原始 `.env`、客户数据、物理用户名路径或整个运行目录；哈希清单本身也不是文件备份。本文是唯一现行规则，收尾记录是具体证据，不能另建多版本有效规格。

## RULE-LCO-003：核实远端合入

获取最新 origin/main，核对仓库、PR、目标分支、远端 merged 事实及对应 SHA。区分：

1. 普通 merge／fast-forward：交付提交可以通过祖先关系检查；仍需核对记录指向的确是本次范围。
2. Squash／rebase：源 SHA 不一定在 main 祖先中。使用远端 PR 合入记录、合入结果在 main 中的可达性及交付增量对应关系综合确认，不能只按祖先检查认定“没合并”。
3. main 后续再次修改相关文件：记录“已交付、主干已演进”，保留历史合入证据；不因当前文件不同就重新投递旧实现。
4. 远端未知、PR 仅关闭或合入来源不符：保留现场并记录原因，不能据此删除原工作或资源。

`patch-id`、忽略空白的 Diff 或文件名相同只能辅助分析，不作为丢弃工作或强制删除分支的充分证据。

## RULE-LCO-004：按增量分类，不把 dirty 等同未交付

对比交付时的来源快照、实际交付对象、最新 main、原工作区当前 HEAD／暂存区／工作文件。

| 分类 | 含义 | 处理 |
| --- | --- | --- |
| delivered-identical | 授权增量已经交付，当前来源仍是所记录副本 | 标注已交付，进入原现场核销；不能重复提交或直接删除文件 |
| delivered-main-advanced | 交付已核实，但 main 后续演进了相关内容 | 不重投旧改动；同步方案需保留新主干行为并处理来源剩余增量 |
| undelivered | 确认是尚未交付的任务增量 | 保留，注明所属任务，不混入无关 MR |
| mixed | 同文件有已交付与未交付 hunk，或有暂存／未暂存的不同意图 | 分别建模、生成保留计划；不能整文件覆盖或核销 |
| unknown | 来源、归属、对应关系或内容存在歧义 | 保留并说明具体需要确认之处；不阻止其他独立安全项继续 |

重命名、删除、文件 mode、符号链接、二进制、LFS／过滤器和新增路径冲突也纳入分类。文本可使用仓库认可的 Git 属性判定规范化对象，同时保留原始字节指纹；不能对所有文件统一替换换行后据此执行删除。

核销清单要区分“交付事实已登记”和“原工作区已完成核销”。仅更新清单而原现场仍留有未处理的已交付副本时，original 仍为 pending／blocked，不宣称工作区已清理。

## RULE-LCO-005：原工作区核销的执行边界

核销的目标是让原工作区对应正确的基线，并保留真实剩余增量，不是抹掉 `git status`。顺序如下：

1. **只读计划**：确定已交付 hunk、保留 hunk、暂存意图、目标基线及可能冲突；复核当前执行授权。只要求写设计或查看状态，不授权改写现场。
2. **隔离演练**：在隔离临时对象／副本中构造“新基线＋应保留增量”，分别验证暂存区、工作文件及未跟踪路径，不能连接业务库或用原工作区试错。
3. **执行前再核对**：原 HEAD、index、相关文件、归属和占用必须仍符合计划；新编辑、main 前进或相关配置变化会使计划失效，重新生成相关部分。
4. **按可证明方法执行**：原现场干净且分支允许快进时可使用正常 `git merge --ff-only origin/main`；脏现场只有经过验证、在授权范围内且不会覆盖剩余工作的增量同步方案才可执行。不得未经授权跨已有分支切换；不以整文件 restore、自动 stash、reset 或强行 checkout 代替增量核销。
5. **执行后验收**：原现场与计划中的“新基线＋剩余增量”一致，暂存意图保持；授权已交付增量不再显示为新的待交付工作；真实剩余工作内容和归属均可核对。

本设计**不把“内容已交付”视为丢弃原文件的自动许可**。当前未实现能够保留混合暂存意图的事务化核销器；脏现场先产出计划和恢复材料，不能让技能凭提示词批量反向打补丁。核销仍需实际安全执行才能完成，无法安全处理则明确 blocked，而非无限保存副本后标 done。

如果中途失败，停止该项，利用该步骤保存的原始指纹和材料仅恢复本次实际写入的部分；出现其他新编辑时不盲目回滚。保留失败记录和已成功项，禁止全工作区重置。

## RULE-LCO-006：临时资源回收

工作区和本地分支分别判断，全部满足各自条件才执行回收：

- 属于本次收尾范围，来源、回收目标明确。历史其他任务的工作区默认只列清单，不因“看起来老”就删除；全仓收尾需有相应范围授权。
- 已交付内容和独有提交完成核对，相关远端合入已确认；没有未交付的改动、未跟踪文件或不明归属。
- 没有其他执行者占用，没有引用该工作区的运行后端、Worker 挂载、终端／工具任务或需要保留的使用关系。Git worktree lock、任务记录和工具元数据属于证据；仅“文件最近没变化”不足以证明空闲，无法确认则保留。
- 忽略文件另行检查。`git status` 干净不代表没有 `.env`、虚拟环境、模型、知识文件、日志、输入资料或恢复证据；应保留的内容已安全转移并校验。用户未要求回收运行环境时，不擅自停服务或销毁卷。
- 已解析并核对绝对路径和允许的边界；不能删除主工作区、仓库公共 Git 目录、外部挂载目标、目录连接的其他目标、其他任务或共享／固定工作区。

托管工作区使用其支持的归档／回收工具并确认结果；普通工作区使用正常 `git worktree remove`，分支使用正常 `git branch -d`。不得用 `--force`、`-D` 或底层递归删除绕过保护；squash 后 `-d` 拒绝时，保留分支并登记原因，不为清理重写历史。

移除后重新盘点路径、Git worktree 注册、本地分支、保留材料和运行依赖，逐项记实际结果。不自动删除远端分支、发布标签、业务数据、容器卷或运行时。只有明确保留策略的资源才用 retained-policy，其余未完成项仍按事实报告。

## RULE-LCO-007：在正确时点收尾并可恢复

- 创建独立工作区时立即登记来源与回收目标；提交前更新精确增量；推送／PR 时绑定源 SHA 和 main SHA。
- 只交付到 PR-open 时生成 waiting-merge 记录和后续动作。技能不常驻等待，不创建未请求的自动任务，也不把建 PR 授权推导为自动合入。
- 当前任务中观察到已授权 PR 合入时，立即执行范围内的本地核对和安全收尾。下次处理同仓交付时先读取相关未完成记录，避免重新交付已合入副本；不自动接管其他任务的写操作。
- 如果会话停止、远端不可达或原工作区被占用，记录具体阻塞及恢复条件。恢复时重新获取远端和本地快照，不使用上次计划直接删除。
- 幂等执行：已经完成且现场未变的步骤仅核验，不重复提交／删除；新出现的工作不被视为旧残留。部分失败不抹去前一步已完成的证据。

## RULE-LCO-008：收尾报告

最终报告分别列出：提交／推送／PR／合入事实，原工作核销结果，临时工作区和本地分支回收结果，剩余工作归属、占用、保留或阻塞原因。说明本次范围内已完成项，并把范围外存量单独列出。

不能将“PR 已合入”报告为“本地全部完成”，也不能将仍保留的已交付文件笼统称为“未合并功能”。没有需要回收的资源时记 not-needed，不为满足流程额外创建工作区或备份副本。

## 自动化边界与实施顺序

| 阶段 | 交付内容 | 允许的自动化 |
| --- | --- | --- |
| 第一阶段 | 交付对应清单、只读分类、合入识别、计划和状态报告 | 只读 Git／远端信息；写本次任务记录；优先防止重复创建和重复投递 |
| 第二阶段 | 经过场景验证的核销／回收工具 | 提供分离的 audit／plan／apply；apply 绑定计划哈希、快照和授权范围，执行前重核对；只回收满足全部条件的对象 |
| 第三阶段 | 现有技能接入工具及恢复入口 | 技能调用确定性工具并解释结果，不自行放宽 blocked 条件或用临时脚本替代未通过的 apply |

当前完成设计并将来源记录、只读核对、收尾模式和恢复入口接入交付 Skill；未宣称以上工具已实现或下列执行场景已通过。apply 不在 audit 失败后自动降级为强删；没有修改授权时仍可完成只读核对并给出可审阅计划。后续工具实现需覆盖以下验收场景，不把“JSON 格式合法”当作安全验收。

## 验收场景

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| AC-LCO-001 | 仅推送并创建 PR，PR 尚未合入 | 请求成功；closeout=waiting-merge；不合入或删除未合入资源 |
| AC-LCO-002 | 普通合入，原开发区干净，临时区无占用且无额外数据 | 正常同步并按授权回收本次临时资源；记录原区与回收后状态 |
| AC-LCO-003 | Squash／rebase，源 SHA 不是 main 祖先 | 识别真实合入；不误重投；本地分支安全删除拒绝时保留并记录 |
| AC-LCO-004 | 原文件与 main 一致，但原 HEAD 旧且 index／工作区有差异 | 分类为已交付副本；不删除文件、不报新功能；执行核销前不宣称干净 |
| AC-LCO-005 | 同文件包含已交付 hunk、新编辑和部分暂存 | 新编辑、暂存意图保持；只能核销可证明的授权增量；歧义项保留 |
| AC-LCO-006 | main 后续重构已交付代码，原现场仍是旧副本 | 标记已交付且主干演进，不把旧副本覆盖回 main |
| AC-LCO-007 | PR 被关闭但未合入，或远端查询失败 | 不回收未交付产出，状态及恢复条件准确 |
| AC-LCO-008 | 计划形成后出现新编辑、index／HEAD／main 变化或路径替换 | 原计划失效，apply 不写入现场；无数据丢失 |
| AC-LCO-009 | 临时区有其他任务改动／唯一提交，或占用未知 | 独立安全项继续；该资源保留并给出明确原因，不混入本次提交 |
| AC-LCO-010 | Git 干净，但存在忽略文件或后端／Worker 引用 | 不直接移除；先明确保存或运行迁移方案，不擅自停服 |
| AC-LCO-011 | 路径含空格／中文，存在目录连接、子模块或嵌套仓库 | 按实际路径和工具限制处理；边界无法证明时不执行递归操作 |
| AC-LCO-012 | 执行途中失败，或成功后再次运行 | 失败项可从记录恢复；已成功项不重复执行；不覆盖新编辑 |
| AC-LCO-013 | 只有文档／配置说明任务，无临时资源 | 不额外创建工作区，不触发数据库或模型测试，不改写原现场 |
| AC-LCO-014 | 全仓盘点发现历史已合并工作区，但本次只授权一个 MR | 列出范围外存量，不自动接管删除，也不让无关存量阻塞本次独立安全交付 |

## 是否适合写入现有 Skill

**结论：适合，已扩展现有 `tea-saas-change-delivery`，不另建第二套交付技能。** 本地来源追踪、远端合入后的恢复入口及收尾报告是跨任务重复流程，能改变执行决策，符合技能用途。此次替换原技能只有一句“合入不等于本地完成”的收尾说明，补充明确的模式、来源记录、状态和恢复步骤。

已进入 SKILL.md 的内容：

1. 增加 CLOSEOUT 模式：用户要求核销／清理，或已授权交付进入合入后收尾时使用；沿用当前授权，不能推导自动合入、跨分支切换或删除远端对象。
2. 隔离交付前建立来源清单；再次交付前识别已合入副本；推送／建 PR 后记录 awaiting merge，合入后分别核对原现场和临时资源。
3. 保留少量必须遵守的边界：按增量保留其他工作，脏区先计划，原区核销与回收分别验收；blocked 项有具体原因，最终报告分开列状态。
4. 按需读取本 SDD 中的判定和验收，并在工具实现后调用 audit／plan／apply。Skill 内的链接应按其实际目录指向 `../../../docs/sdd/governance/local-delivery-closeout.md`，不要复制整套规则。
