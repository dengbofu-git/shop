# 系统事实归属及任务依赖

规格0.3.0，2026-10-28。技术保持Django多App单体、多页面模板／JS；MySQL为业务及会话，PostgreSQL/pgvector为知识与显式偏好，Redis为缓存／采购车；外部模型、本地embedding／reranker及OTel按实际任务与配置参与。

## 数据所有权

| 领域 | 拥有事实 | 消费者约束 |
| --- | --- | --- |
| IAM | 当前身份、启用状态、角色权限和地址归属 | 请求／模型自报身份不授权；产品三类角色与内部RBAC分开 |
| CAT | 公开商品、价格、属性、上下架 | 可展示与可购买集合分离；模型不得编价或私有属性 |
| TRD | 类型状态、金额、可信付款、订单快照 | AI只读，不从历史回复推断实时状态 |
| FUL | 仓库账本、预留／释放／出库、物流事实 | 按[库存规格](../modules/trade/stock-reservations.md)统一，未知物流不补造 |
| MER | 本商家协作、指标、结算记录 | 快照归属优先，混合历史单不整单操作；展示不等于真实清结算 |
| AI | 有限任务编排、会话、结果引用、输出与错误 | 执行器控制依赖和权限；没有交易写工具 |
| KNOW | 公开／私有知识范围、向量空间、本人显式偏好 | 可选读取失败须显式，不能伪装无记录 |
| PLAT | 运行配置、权限导航、观测和交付 | 不复制交易规则或据统计臆造行业事实 |

## 按任务装配（R01／R02）

请求先认证、校验会话及重放，再按任务读取所需事实。普通订单查询仅依赖必要业务服务，普通知识问答依赖知识事实；偏好只有明确偏好任务才为强依赖。外部模型仅用于需要它的解析或表达，确定性工具可独立完成已明确的请求。

某工具失败不使独立工具失败，依赖该结果的步骤跳过；请求级认证／会话越权不能部分放行。部分成功的HTTP及保存策略见[订单契约](../modules/ai-support/capabilities/CAP-AI-003/api-contract.yaml)。

0.24.0已按任务经 MCP 读取偏好；普通推荐可选、明确偏好任务必要。后端单次旧连接重读只解决已识别传输故障，不重放整轮。不得用模型回答替代不可用的业务数据库，也不能把没有检索证据说成已验证知识。

## 事务、幂等及运行

订单使用MySQL短事务、统一锁顺序和请求幂等；购物车不是库存事实源。会话成功／部分成功持久化与revision原子提交，订单工具仍只读。模型调用在事务外，不能承诺回滚已经发生的外部调用。跨MySQL／PostgreSQL不依赖一个事务自动覆盖。

历史读取、模型上下文和成功重放分别投影；真实订单及结果位置映射只存应用私有范围。源码、隔离结果、本地启用与远端发布分别记录，当前事实见[差异矩阵](../product/current-state.md)。

## 模型 Agent 数据入口

2026-10-28用户确认模型 Agent 的数据访问统一经 MCP，完整边界见[访问规范](agent-data-access.md)。宿主为模型读取持久化历史或偏好也属于该入口；认证、会话控制和保存继续由后端负责，普通业务 API 与 PDF Worker 不机械迁移。MCP 后端复用可信领域服务，不能代替 HTTP 鉴权，私有工具需独立绑定认证上下文。

当前客服主链已改为请求级 stdio MCP，并保留原独立开发者公开详情入口。移除的是 Agent 侧直调及本地降级，不是后端查询函数。[运行设计](../modules/ai-support/mcp-runtime.md)说明授权、私有状态及预算；[迁移清单](../modules/ai-support/mcp-migration.md)为实施前盘点。隔离验收不代表业务服务已经重启或实现了物理凭据隔离。
