## 真实模型合成验证

固定起始配置：`deepseek-flash`、修订 **5**、思考模式开启。商品仅在内存 SQLite 构造；知识片段为合成测试素材，未搜索、读取或传送生产知识。历史上下文仅来自本次合成轮次。未将测试会话写入业务会话或运营数据库。

最终 **7 组、17 轮全部满足预设检查**，14 次模型调用；SDK 统计输入 28,319、输出 18,218 Token，不作为费用账单。见 [最终摘要](live-summary.json)、[逐轮结构化记录](live-results.jsonl)及[可读对话](live-dialogues.md)。

| 场景 | 检查 |
| --- | --- |
| 缺币种 → 补充美元 → 修改价格 → 新推荐 → 取消 | 保留预算、品类和数量；新请求清除旧预算，取消清空状态 |
| 说明两类茶 → 对应推荐 → 解释原列表 → 第二款价格 | 顺序、证据范围和商品引用保持，详情重新读取合成商品当前值 |
| 六类各一款及理由 | 六类齐全，程序分组，无虚构用户硬条件 |
| 本人已保存偏好 | 使用已核验软偏好，不能变成硬条件 |
| 缺项期间问候再继续 | 问候保留待补充状态，后续能继续 |
| 商品序号越界 | 澄清，不猜商品或做替代推荐 |
| 无可验证认证属性 | 澄清，不虚构商品认证 |

探索阶段曾出现：合成知识素材缺少具体内容、理由检查允许空集合、模型把六类范围展开为无原话条件，以及把偏好附加到独立问句。素材和判分修正、应用修复均已明确记录；早期 14/17、16/17 与最终结果不能当作同条件准确率提升对照。原始记录见 [探索轮次](exploration-results.jsonl) 和 [中间轮次](intermediate-results.jsonl)。未删除失败记录。最终17轮只代表这组样例，不证明生产流量准确率或模型稳定性达到100%。
