## 本次结论

成本控制有效降低了本样本开销，但不能认定质量无损。相同业务、同日配对的已知usage费用从每100条$0.120208–$0.240416降到$0.026314–$0.052628，减少78.1%；平均耗时16.823s降至6.771s，减少59.8%；P95从72.662s降到26.332s，减少63.8%。

原自动约束两组均83/100；按相同标准逐条复核重点答复后，对照75/100、优化74/100，改善3条、退步4条。自动总分不变掩盖了具体回退，不能只看通过率或只看费用。

- 改善：R045补足阿联酋习俗资料缺口说明；R051完成CTC/Orthodox回答，避免长时间后失败；R054恢复有证据的冲泡参数说明。
- 回退：R018排除绿茶/红茶的语义证据校验失败；R026送礼请求没有产出商品；R048/R052将“稍后供茶”具体化成“餐后供茶”，核验漏检。R046优化后同样出现该时间越界，但对照本身服务失败，严格判分两边均未过，不列为新增回退。
- R018仅输出305 Token，远未达到1400的规划上限；预算拒绝次数为0，明确诊断为“意向条件无法对应输入证据”。这不是本轮Token预算截断所致。
- R028优化后虽恢复推荐与理由，附加六类茶说明却把black tea误译，列表出现两个“黑茶”。与对照的全局误拒绝一样，整条都未通过；不能把商品卡存在当成回答准确。

模型请求178降到132；其中通用合规复核36降到0、知识草稿30降到23、语义核验23降到20；意图规划55次及查询改写34次均未减少。思考Token从150557降到0，非思考输出反而从26753略增到27213，说明主要省掉的是思考和重复处理，并非简单缩短用户答案。没有请求级模型预算耗尽，优化组API全部132次200且均返回usage；对照4次缺失usage，潜在实扣不在费用表中。

建议保留预算、参数修正及减少重复审核，但不要仅凭本轮费用下降就宣称全阶段关闭thinking可以无损替代。后续应对规划证据绑定、语义核验的时间/茶类翻译边界单独改进或小样本比较；本轮未调整代码来追求更好的分数。

## 控制变量和范围

- 输入为上一轮完全相同的100条问题、115个公开可售SKU快照、27笔合成订单、隔离红茶偏好；会话顺序相同。长期偏好仅5条专项输入，其他图输入为None。数据仍使用SQLite隔离，不读真实买家历史、订单或偏好。
- 两组冻结相同当前业务代码和全部本地Python依赖源码；仅6个成本相关文件不同：模型适配、知识/茶类重试、执行器预算提示、组合审核和图请求预算接入。before为同业务的反事实对照，非旧部署复刻。精确源码差异见source-manifest.json。
- 使用同一PostgreSQL REPEATABLE READ READ ONLY共享快照，所有检索强制owner=None，仅公开已发布知识。真实Ollama嵌入、pgvector召回、RRF、重排和模型链路；未修改生产服务与数据库。
- 全局模型配置沿用上轮deepseek-flash、thinking=enabled、revision=5、temperature=0、调用方timeout=45、SDK重试0、调用方max_tokens=4096；优化组再按本次阶段策略及请求预算收紧。before实际开启thinking，after六阶段均关闭；实际HTTP参数与usage逐次记录，不以全局配置字符串替代实际开关。
- before恢复旧适配器的max_completion_tokens发送方式、thinking及重试/复核流程，after采用max_tokens和分阶段开关；比较的是本次成本控制整体，不能归因于其中单独一个改动。
- 图与工具集成测试，包含按条构建模型客户端开销；不是浏览器、HTTP提交/重放、数据库吞吐或独占硬件压测。本地服务与外部模型仍受负载、缓存和服务预算影响。
- 自动约束与人工复核分别保留；知识事实以冻结片段为依据，不是独立专家/外部世界事实审核。超时、错误、澄清和退步均计入，不用重试替换失败记录。每题每组一次，未重复多轮；thinking模式不保证temperature=0生效，不能宣称完全确定性。

## 费用口径

本轮全部200条完成后，控制器等待工作进程退出30秒超时。完成标记和310次HTTP记录已全部落盘；随后只读检查两个本次Python工作进程已自行退出，无残留，未强制终止或重启数据库/模型服务。该收尾异常不计入单条耗时，保留在cleanup.json。

使用HTTP实际usage的缓存命中、未命中及输出Token分别计价，思考已包含在输出中不重复计费。依据DeepSeek官方每百万Token非峰时缓存命中$0.003、未命中$0.15、输出$0.6，峰时两倍。表中范围为同一用量按两种时段计价；缺失usage请求可能仍实扣，不构成完整账单上下界。本地嵌入/重排无新增按Token API费，但硬件和用电成本未折算。来源：[DeepSeek官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。

本地服务状态和耗时见summary.json；429、客户端超时及降级保持原记录，不能声称是无噪声的纯算法基准。模型平台缓存跨组共享、AB/BA交替只能降低顺序偏差，不能消除所有波动。
