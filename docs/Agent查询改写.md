# Agent知识检索与按需改写

本次检索实现增量为support_ai 0.22.0、ai_storage 0.6.0；工作区模块总版本以versions/modules.json为准。历史设计及历史评测保留在下方，不代表本次参数和默认行为。

## 当前链路

脱敏并规范化的知识子问题 → 原问与规则别名 → 全文/向量权限内召回 → RRF去重 → 仅原问题重排 → 按对象覆盖选择证据 → 缺口触发最多一次改写和补检 → 有依据生成及独立核验。

模型不生成SQL、不决定owner；Python工具执行数据库查询。长期偏好不自动混入知识查询。全文与向量均先限制已发布内容、公开或当前可信owner私有文档。全文可以召回已发布但尚无向量的片段；向量通道继续限制EmbeddingSpace。

## 召回与预算

首轮不调用翻译，使用原问题与程序词典扩展。默认总候选30，全文占一半、余量分配给原问和规则变体；不足2个候选预算时只执行向量通道。每路独立失败，RRF使用1/(60+rank)融合不同排名，不相加异构原始分数。全文采用PostgreSQL simple全文解析、中文双字词、SearchRank和GIN；不是BM25或完整中文分词器。

重排前按已知比较对象预留候选，再限制到min(配置召回候选数, 服务端重排上限)，默认上限20；重排查询始终为原问题。证据条数/来源/阈值继续受运营配置约束，字符预算额外限制单对象3000、多对象8000。标题和章节用于搜索索引，不当成引用原文；旧向量保持原输入策略。

无证据、已知对象与所问主题未同段覆盖、主题缺口、明确年份缺口、弱重排相关信号可触发一次补检；单纯“只有一个片段”不触发。最多生成两个新查询，同一请求所有知识步骤共享一次改写模型调用。补检无新增候选不再重排；有新增候选但覆盖质量变差时保留首轮证据。词典和覆盖均是有限启发式，不是准确概率或任意实体语义保证。

审计增加channel、cache_status与coverage（covered_subjects/missing_subjects/missing_facets）；保留remaining_issues、retry、最终selected_ids。资料缺口通过既有notes传给生成，不能自动扩展结论。全部失败、或者无证据同时存在召回技术失败时抛出技术错误；向量故障而全文有有效证据时允许降级，但不缓存该不完整检索结果。

## 缓存

嵌入缓存绑定模型服务、模型/版本及空间。证据缓存绑定数据库身份、知识epoch、owner/公开范围、查询、配置、重排版本及服务端检索预算；命中仅跳过检索，不缓存订单、答案生成或核验。默认TTL300秒，上限3600秒，可关闭。

PostgreSQL触发器覆盖片段和文档的新增/批量更新/删除/撤回、标题更新及模型空间更新，知识epoch随同事务提交，下一次请求不命中旧证据。数据库事务内部禁用证据缓存；epoch查询失败不允许用旧值。缓存服务失败回源，空结果、路由错误、改写错误、重排降级或仍有缺口均不写证据缓存。数据库备份恢复后应清除缓存。

## 历史设计与历史评测（下文不代表当前默认实现）

# Agent 查询翻译、扩展与补检

版本：support_ai 0.9.0 / ai_storage 0.3.2，2026-10-16。

重排输入增量：support_ai 0.20.1，2026-10-26，见文末说明；上行为初始设计版本。

## 运行链路

```text
脱敏输入 → 同会话指代补全 → 有限任务与知识子问题
  → 原查询 + 翻译查询 + 术语扩展（首轮最多4条）
  → 按固定所有者权限分别向量召回
  → RRF融合、去重 → 仅原始检索问题与原文片段重排序
  → 按主题覆盖和上下文预算选择证据
  → 不足时最多一次补充改写与召回（最多2条新查询）
  → 合并后再排序，保留质量较好的证据 → 有依据的回答
```

网页客服和终端预览都使用同一个请求级 `KnowledgeRetriever`。
同一请求内共享模型调用预算与Embedding缓存；不跨请求、账号或公开/私有范围缓存证据。
直接调用 `retrieve_knowledge()` 也默认启用新链路，但多次独立调用不会共享请求预算。

## 1. 翻译与跨语言规范化

- 对查询做Unicode NFKC和空白规范化；翻译前脱敏，阿拉伯文术语匹配忽略元音符号及延长线。
- 使用当前运营配置中的DeepSeek模型生成结构化翻译。目标语言默认中文、英文，可配置增加阿拉伯文。
- 原始查询始终保留为首轮第一条查询；不将翻译问题当作事实证据，不翻译或改写数据库中的知识正文。
- 维护六类茶与中东国家术语，明确 `black tea=红茶`、`dark tea=黑茶`；饮茶习惯不等于进出口或消费量。
- 对模型变体检查已知茶类/国家集合、已知主题集合及数字的一致性。不接受新增已知对象、数字或改变主题的变体；无法可靠校验否定/排除语义时放弃自由翻译，保留原问及字面词典扩展。
- 这些检查是保守的启发式约束，不能证明任意语言或任意实体的翻译完全等价。未收录实体的变化仍可能无法识别。
- 独立知识追问使用经历史引用校验的 `resolved_question`；显式多任务保持知识子任务范围，避免把购买条件混入检索。

## 2. 同义扩展与多路召回

- 术语词典提供中文、英文及部分阿拉伯文别名；模型还能生成最多两个同义表达。翻译和扩展共同受首轮4条查询上限约束，重复查询折叠。
- 六类加工说明已有程序确定的范围，直接生成固定双语模板，避免六类分别调用翻译模型。
- 每路均调用既有的 `search_knowledge()`：只查询同一Embedding空间、已发布内容和当前可信所有者可访问的文档，不通过改写决定权限或生成SQL。
- 首轮总候选条数保持运营配置的 `retrieval_candidates`；优先给原问分配约一半额度，其余分给变体。
- 使用RRF融合名次，`score = Σ 1/(60+rank)`，不直接相加不同查询的向量距离。融合后候选池仍受当前候选上限约束，并按正文去重。
- 重排序只使用原始检索问题（进入retrieve_knowledge并经既有脱敏、规范化后的query），不拼接翻译或扩展查询；首轮和补检后统一使用同一原问锚点。最终证据仍受运营配置中的阈值、条数、来源和字符预算约束。
- 多对象问题优先保留能同时覆盖某一对象及所问主题的片段，然后填充其余相关证据。

RRF公式参考：[Elastic 官方文档](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)。项目直接实现排名融合，无需安装或部署Elasticsearch。

## 3. 证据不足与一次补检

以下信号可触发补检：

- 没有证据；
- 证据数量少于 `min(2, retrieval_top_k)`；
- 最高重排序分数低于配置的弱相关阈值；
- 已知茶类/国家与所问主题没有在同一片段中覆盖。

例如比较两国饮茶习惯时，某国消费量预测片段不能满足该国习惯主题的覆盖检查。
覆盖通过也不等于事实已核实，分数阈值只用来决定是否再检索，不作为准确率或事实判定。

补检只向改写模型发送脱敏知识问题、先前查询和原因代码，不发送召回正文或历史订单数据。
程序还会为缺失的已知对象构造定向术语查询，最多实际补查两条未尝试过的新查询；没有合法新查询或预算耗尽时直接停止。
补检候选额度最多为首轮一半（至少1）；两轮总额度最多为 `N + max(1, N//2)`。
合并后只在覆盖缺口、数量/弱相关信号和最高分组成的启发式质量没有变差时采用新证据；补检服务失败保留首轮证据。
这些指标不能保证语义质量单调提高。

补检后仍不足的普通知识任务会向生成/合规节点传递中文资料限制，并返回到 `unmet_requirements`；没有证据则返回知识不足，不循环搜索或编造答案。
分茶类结构化说明继续执行原有逐字引文、分类范围校验及依赖推荐约束。

## 请求预算与降级

- 整个客服请求最多调用改写模型2次，单次默认5秒、无SDK自动重试，输出上限1400 Token。
- 附加检索操作默认使用25秒派发预算，从第一项知识检索开始计算；后续茶类共享此预算。
- RAG Embedding读超时最多8秒、连接超时2秒，并按剩余预算缩短；批量导入的默认超时保持原行为。
- 重排序超时不超过运营配置与剩余预算，服务异常继续使用既有允许降级/拒绝降级开关。
- 25秒是附加操作派发预算，不是整轮硬超时：原问保底召回、在途HTTP请求、PostgreSQL执行及答案生成仍可能超过它。
- 翻译异常或变体被拒绝时，使用原问和可用的词典扩展；单路失败不影响其他路。

## 原问题重排增量（0.20.1，2026-10-26）

用户确认改为仅使用原问题重排。多路召回仍可使用翻译和术语扩展，RRF融合候选后，首轮和补检后均以原始检索问题调用重排模型；关闭改写的单路路径原本已使用该问题，不另行改写。显式知识子任务和已校验的追问补全仍在进入检索前按既有任务范围处理，不改用未脱敏的整段客户原话。

依据为[本次独立组件A/B评测](../reports/agent-evaluation/2026-10-26-rerank-query-ab/run-2/report.md)：固定15题及每题30候选，90次真实重排全部成功；原问／拼接的nDCG@5为0.8780／0.7777，平均10.66／12.52秒，CPU42.67／50.11核秒。拼接P@5有局部收益，不能宣称每题都退化；小型英文知识快照回归和非独立专家标注也不证明普遍或总体统计显著优势。

组件评测关闭了补检与回退，不包含完整Agent编排及弱相关触发的额外开销。本改动不调整这些策略或阈值，既有低绝对相关分数仍可能触发补检。组件实验不替代源码修改后的端到端验收，本次未新增或运行自动化测试／真实模型调用。
