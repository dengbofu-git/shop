## 1. 用户主题继承

- 最近用户原话中的单一明确茶类可以传给下一次宽泛推荐，覆盖模型从更旧历史猜出的分类。每个继承条件带原始 `turn_id` 和逐字引用，继续执行普通证据校验。
- 用户本轮明确茶类、跨类推荐、重置范围优先。多茶类比较后的宽泛推荐先澄清范围；否定、排除和切换等复杂语义使用既有模型解析与来源校验。
- 助手知识说明、推荐商品分类和长期软偏好不会自行成为用户硬条件。已有明确预算、品牌、排除条件会进入完整抽取路径，不能因使用简单分类规则丢失。
- 历史仍受原有最近 24 小时、最多 6 轮、6000 字符预算约束；不承诺跨会话或无限轮记忆。

## 2. 已有商品解释工具

- 新有限意图：`recommendation_explanation`；固定工具：`explain_recommendations`。
- “给出推荐理由”“为什么推荐”等已有列表追问绑定最近列表；同轮新推荐附带的“并说明推荐理由”在本次推荐中输出依据。显式要求解释之前列表时从历史列表绑定，不挪用后面的新推荐结果。
- ID 只来自服务端保存的工具结果；兼容旧记录时使用商品名和规格精确唯一匹配。没有列表、位置不合法、单数指代歧义或旧名称不唯一时请求澄清。
- 按绑定的 SKU 查询当前可售状态、价格、库存及允许的属性。缺货/下架商品明确说明，不替换成其他商品。历史价格和库存继续不进入会话上下文。
- 输出分类、品牌、已确认单份美元预算的匹配，以及当前包装、净含量等属性。每 100 克价格由 Decimal 计算；最低单份价格、最小包装只在绑定列表内比较。虚拟商品属性保留“模拟”标签。
- 理由工具不调用条件抽取、全库匹配或生成模型；单工具回复由确定性格式器输出。多任务仍走既有组合与安全检查。
- `explained_products` 与新 `recommendations` 分开保存；`recommendation_references` 保留所解释对象（包括当前不可售对象），后续追问仍能定位。服务端历史筛选依据仅供理由说明，不作为新用户证据。

## 3. 抽取契约与诊断

`IntentEvidence.field` 仅允许：

- `required.categories`、`required.brands`、`required.keywords`、`required.price_min`、`required.price_max`、`required.currency`、`required.price_basis`；
- `preferred.categories`、`preferred.brands`、`preferred.keywords`；
- `excluded.categories`、`excluded.brands`、`excluded.keywords`。

数组元素分别提交证据，字段路径不带下标。数量、任务上限、理由、action、missing_fields 不属于证据筛选字段。结构、原话来源、条件一致性均继续校验，不通过时不能查询商品。

模型契约或来源校验失败最多纠错一次，重新提供同一份脱敏输入与安全字段诊断，不回填或丢弃非法字段来放宽筛选。两次均失败返回工具 `error` / 推荐 `ERROR`；只有真实业务缺项才走 `needs_clarification`。全工具失败沿用 HTTP 503/终端失败记录，不写入成功会话。

成功或失败诊断保留 `condition_source`、`extraction_attempts`；主题继承保留 `topic_inheritance`。错误不输出模型原始返回或可能含输入值的异常正文。
