## 背景与决定

买家看到三笔订单后追问“第二笔发货了吗”，不能重新按最新创建时间取第二笔；中途插入订单会改变其含义。按买家和会话绑定当前已展示页，以最多20个真实订单编号、查询条件、查询时间和提交序列记录在专用 Redis 键，24小时自动到期。客户端和模型只接收匿名位置，不持有该映射。

SQL 成功提交轮次后才发布映射；Lua 比较序列，迟到写入不能覆盖更新页。读取时核对本人会话最新已提交订单结果序列，再以本人且未隐藏范围重读该订单当前状态。新查询和下一页替换当前页；成功重放不重新发布或续期。Redis 丢失、不可用、位置越界、歧义或已不可见时澄清并请求重新查询，普通过滤查询仍可用。

## 取舍与边界

Redis 自动到期适合短期位置引用；不新建业务表，也不在公共响应、聊天正文或模型上下文存真实订单编号。相比重新排序，映射稳定；相比持久表，减少清理和迁移负担，但接受缓存失效后必须重新查询。SQL 与 Redis 无分布式原子事务，因此用提交后发布与序列核对阻止旧页误用，不能保证缓存总可用。

该批准只确认当前页映射方案，不确认聊天数据库、日志或监控保留期；Q-013 其余范围仍开放。未授权运行启用。验证见[本轮证据](../sdd/evidence/2026-10-30-rule-implementation/verification.md)。
