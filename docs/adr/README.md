## 命名和状态

文件名使用 `NNNN-<短名>.md`，从 `0001` 递增，写入前检查已有编号；并行任务发生编号冲突时在交付前协调，不覆盖已有记录。

状态使用 `proposed`、`accepted`、`rejected`、`superseded`。新提议默认 `proposed`；只有实际决定者明确确认，才记录 `accepted`、确认人及日期。测试通过、AI 建议或任务标为完成都不构成批准。已有明确决定可以补录，但必须引用可核对的确认依据。

已接受的决定保留原理由。发生替代时新建 ADR，旧文标明 `superseded` 并双向链接；不要把新方案改写成历史上已经决定的事实。影响业务语义的选择同时更新相关 CAP 并按现有 SDD 流程评审。

## 可复制模板

```markdown
# NNNN 决定标题

Status: proposed
Date: YYYY-MM-DD
Decision makers: 待确认
References: 相关 CAP、规则、源码或讨论依据
Supersedes: none
Superseded by: none

## 背景与问题

实际约束、受影响模块和需要决定的问题。

## 方案与取舍

列出可行方案、选择理由及未采用方案的代价。

## 决定

当前为提议；确认后记录精确结论、确认人、日期及确认依据。

## 影响与验证

说明兼容、权限、数据迁移或回滚影响；链接实际验证，未执行则明确标记。
```
