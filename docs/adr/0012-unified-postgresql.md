# 0012 统一 PostgreSQL 数据库与默认事务连接

Status: accepted
Date: 2026-11-02
Decision makers: dengbofu
References: 本聊天先分析全量使用PostgreSQL，用户明确要求“先把统一PostgreSQL作为独立迁移任务完成”；此前三层记忆方案不在实施范围。

## 决定与范围

业务、会话、偏好、运行记录与知识使用一个 PostgreSQL 数据库，通过 default 连接访问；不把两个别名指向同一物理数据库冒充同一事务。Redis继续承担采购车、限流、缓存及已确认的24小时订单位置映射；媒体/PDF文件保持文件存储，MCP授权边界保持。

`TEA_SAAS_DATABASE_MODE=unified`为默认，使用POSTGRES_*。显式legacy模式仅用于旧来源读取、迁移及恢复；不作为第二个并行运行版本。现有AI_STORAGE_DB_ALIAS辅助实现与旧隔离夹具兼容，统一运行时为default且不注册ai_storage连接。

## 迁移和恢复

来源只读导出，目标必须新建、具备准备收据且仍与初始化基线一致；历史Migration不改写。目标按迁移建表，统一保留两库原ID、列值、购买快照及历史NULL币种，逐表规范化摘要核对。初始化产生的种子数据只在受保护的新目标中替换。外键/向量校验始终启用，导入后校准序列。

只对目标的知识修订号派生触发器暂时停用以保留原数据；外键延迟事件排空后恢复触发器。全部导入与内容校验在目标事务内完成，失败回滚；已应用收据禁止再次覆盖。

最终一致快照要求暂停本项目写入进程；保留来源库与原生备份，统一库原生备份需实恢复校验。新库接收业务写入后不得仅改配置切回旧库，必须处理新增数据。部署/启用证据另行记录，不从本ADR推断已切换。

## 比较规则与验证边界

原MySQL文本使用utf8mb4_unicode_ci。PG默认排序规则不同，不能宣称所有语言的比较/排序逐字等价。账号登录/注册显式忽略大小写，返回数据库保存的规范账号名；新增Upper(username)唯一约束保护并发注册。商品导入按本店与批次显式处理大小写重名。普通全文检索继续使用既有中英文词项、索引和ACL，不新增全库不确定排序规则。

初步迁移对所有既有记录逐列保真；新增输入按上述明确规则处理。其他重音、兼容字符及语言排序的统一规则未获单独业务定义，不借此扩大字符串归一化或改写现有账号。

真实PG回归必须执行原MySQL专属的库存、发货、咨询、评价和导入并发用例；SQLite或被跳过的测试不作为该证明。慢模型、OCR/embedding不在数据库事务内；即便单库，后台作业仍需要可靠投递和幂等。
