# 0013 PostgreSQL 唯一运行后端与旧源数据退役

Status: accepted
Date: 2026-11-03
Decision makers: dengbofu
References: 用户要求暂搁记忆管理，优先完全替换PostgreSQL，完成后删除旧项目库内数据并验证独立性；随后授权最高优先级和中断同仓其他任务。
Supersedes: [ADR0012](0012-unified-postgresql.md)中的运行legacy兼容及原源继续保留数据安排。

## 决定

正式运行只有PostgreSQL/default。显式legacy及未知模式均拒绝，不从DB_*、AI_POSTGRES_*推断运行目标，不保留自动回退。移除旧源测试启动器、来源导出入口和可选运行依赖；离线归档的PG准备/导入/核验保留。SQLite仅用于合成单测，不构成业务运行替代。

评测、种子与专用PDF测试均使用PG身份守卫；操作员工具同时核对数据库名与集群system identifier，权限不足或身份不明直接失败，不放宽为只比库名。历史Migration不可变，历史证据继续说明原时点。

## 旧源退役

只处理已核实原容器、原数据卷和服务器UUID的旧项目库。最新原生备份须在无网络、无端口、全新临时实例中实恢复且逐表内容一致；若有未进入归档/PG的来源增量，保留并先核对，不能直接清空。

用户授权删除库内数据，执行范围为旧项目库全部已核验表的行数据，保留空结构、原实例/卷及离线备份。禁止删除其他项目库、共享卷或系统表；跨库外键、未知对象或新写入均使清理中止。执行前后记录表集合、行数、身份和备份哈希；实际结果另记证据。

## 独立性与恢复

在只有PG/Redis的内部网络、仅提供PostgreSQL驱动且旧引擎端口不可用的干净环境，运行业务、原生MCP及专用PDF数据库验证。旧项目库清空后还需验证主服务、知识Worker、清理进程及真实只读接口，证明不依赖残留数据。

恢复只能从备份进入独立恢复环境，不重新开放正式运行legacy模式；新PG已接收业务写入，不能盲目回退。不同进程、Redis、模型及外部支付仍不属于同一SQL事务。记忆管理、交易政策和真实支付渠道不在本任务范围。
