# 0004 订单预留与数据库库存事实源

Supersedes: none

## 背景与决定

购物车检查不能保证订单承诺，发货扣减无法避免收款后缺货。采用MySQL事务中的订单仓库预留，按账号及库存行锁串行校验；仓库账本为可售事实源，SKU库存为实物投影及无账本时的旧数据回退。加入购物车不占库存。

预留有固定时限、账号累计额度与累计占用预算、重复取消冷却及来源频控；付款确认保留预留，取消／超时释放，发货消耗本单预留。由数据库维护最终不变量，Redis仅保存采购车，不依赖其可用性判断库存。

## 取舍与边界

单库事务保证多店结算全部成功或回滚；店铺订单和预留仍独立，固定顺序取锁，幂等编号防重试重复占用。当前规模不引入分布式锁或跨库库存事务。

选择订单预留意味着免费占用仍需额度和业务成本控制；来源IP不是人的唯一身份。本轮未接入企业认证、设备风控或真实定金，不宣称可以消灭多账号、多来源攻击。大额采购由现有联系商家入口确认，不生成虚构审批结果。

支付只接受可信异步证据，库存释放后的迟到付款保留异常并人工处理退款；不通过恢复订单或负库存掩盖资金与库存竞争。历史订单不自动补造预留。
