# 任务分诊标签

本项目在本地 Markdown 任务的 `Status:` 行使用以下五个标签。它们描述下一步处理方式，不是 GitHub Issue 标签配置，也不是 SDD 生命周期。

| 标签 | 含义 | 后续处理 |
| --- | --- | --- |
| `needs-triage` | 新问题尚未完成范围和影响判断 | 核对现状、相关模块和规格，再决定下一步 |
| `needs-info` | 缺少复现、业务结论或必要输入 | 写明缺失信息及相关开放问题；继续不依赖该信息的工作 |
| `ready-for-agent` | 范围、依据和验收明确，可由 Agent 在已有授权内实施 | 开始时登记执行者和进度，不自动提交或推送 |
| `ready-for-human` | 当前需要人工决定、操作或处理 | 说明具体原因及需要的人工作业，不把它视为批准 |
| `wontfix` | 已明确决定本次不处理 | 记录决定依据、范围和实际决定者；需要时可以重新分诊 |

推进方式见[任务记录](issue-tracker.md)。完成情况写在 `Progress` 与“结果与证据”中；未知事项不能仅因静态检查或测试通过变成已批准结论。
