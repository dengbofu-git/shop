# 按商家独立订单与结算组风控 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development / superpowers:executing-plans；遵守本仓授权，不自动执行技能示例Git提交。

**Goal:** 保留按商家独立订单／付款／履约和整次原子建单，移除1800秒逐店预算及3子单上限，按有效待付结算组和异常释放事件控占位。

**Architecture:** 沿用CheckoutRequest关联一次提交；用户锁内校验待付组并原子创建各店OrderInfo/StockHold/清理任务。PG持久化按组去重风险事件及固定冷却，独立商家状态不合并；现有库存、金额、数量、20SKU及15分钟不变。

**Tech Stack:** Django5.2/Python3.13、PostgreSQL16、Redis7、模板和Node测试。

**Spec:** 本chat用户确认按商家拆分后明确要求“实现”；对应[预留规格](../../sdd/modules/trade/stock-reservations.md)本轮修订。后端在主工作目录开发，原PG／登录Hash／轻量结算及外部web WIP保留。

## Global Constraints

- 每个商家独立订单、金额、付款、取消、发货、评价／售后；组只作内部关联及统计，不合并交易或付款。
- 每组20种不同SKU上限配置化、重复SKU拒绝；新单同900秒截止、重试／部分付款不续期。
- 同账号最多3个仍有有效未付reserved hold的组，替代3笔子单；旧有可信checkout关联复用，NULL各单兼容，未预留旧单不占组。
- 全账号300件／60000元、店铺及同SKU占位额度不扩张；数量金额仍按实际未付订单聚合。
- 1小时3组未付超时冷却30分钟；5组取消后再创建触发10分钟，24小时内再次触发该取消规则升级30分钟。按组同类最多一事件，失败请求不计占用，平台／商家取消不罚。
- 新事件游标避免同批历史在冷却结束后立即重触发；冷却只挡新建，重放／付款／取消仍可用，页面刷新不延长。
- 实现与隔离验证授权；未授权业务库0008应用、重启服务、提交／推送／PR。历史Migration不修改。

## Review Focus

- 部分付款／取消的组剩余未付占用继续占1名额，已付库存不因退出未付统计释放。
- 用户锁下同时准入与创建，两个请求争最后名额最多一成功；同请求回放不增加组或事件。
- 一次3店同时到期只记1超时；小额部分付款不能免除其余超时，重复清理不重罚。
- 冷却落库后才在事务外抛拒绝，避免随建单回滚丢失；库存／价格失败仍整批回滚。
- 历史回填只用受管关闭单、真实released hold及可信时间，不猜相近时间组、不延长截止、不改库存。
