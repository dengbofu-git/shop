# tea_saas 运行日志

更新：2026-10-19。已实现统一输出、隐私过滤、HTTP 请求关联和当前 Agent Trace 关联。完整规则见 [SDD](sdd/modules/platform/runtime-logging.md)。

## 配置

在本项目私有 `.env` 或服务进程环境中设置，重启后生效：

```dotenv
LOG_LEVEL=INFO
LOG_FORMAT=json
LOG_TO_FILE=false
LOG_DIR=logs
LOG_MAX_BYTES=10485760
LOG_BACKUP_COUNT=5
```

`LOG_LEVEL` 可用 DEBUG／INFO／WARNING／ERROR／CRITICAL；`LOG_FORMAT` 为 json 或 text。无效级别／格式回退 INFO／json，无效轮转数字回退默认值。DEBUG 仍不会输出 SQL、请求正文或自由文本。

本地单进程需要文件时设置 `LOG_TO_FILE=true`，生成 `logs/application.log` 及 `.1` 至 `.5`。默认目录已经忽略 Git；自定义目录应位于私有可写位置，并自行加入忽略规则。不要放在 static／media 下，不通过 HTTP 暴露。控制台输出始终存在，文件与控制台是同一日志的两个副本，统计时不要重复计数。

10MiB × 当前文件加 5 个备份约为 60MiB 容量，单条记录触发轮转时可能短暂超过阈值。轮转不是 14／30 天清理策略。多个 Web 进程不得写同一个轮转文件；部署环境关闭文件输出并交由外部采集。只读或失效文件目录不会阻止 Django 启动，首次写入失败后文件输出降级，恢复需修复权限并重启进程。

## 定位问题

从浏览器网络面板取得响应头 `X-Request-ID`，在日志中按 `http_request_id` 查询。它每次 HTTP 请求都不同，与聊天 JSON 内用于幂等的 `request_id` 无关。

例如以下为合成的业务失败事件：

```json
{"timestamp":"2026-10-19T00:00:00.000+00:00","level":"WARNING","service":"tea_saas","logger":"tea_saas.request_logging","event":"http.request.completed","http_request_id":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","method":"POST","route":"v1/users/login","http_status":200,"business_code":10003,"duration_ms":8.5,"outcome":"business_error"}
```

HTTP 200 不一定代表业务成功，应结合 `business_code` 与 `outcome`。响应过大、流式响应或没有整数 code 时只依据 HTTP 状态记录，不推断业务结果。开发服务器／反向代理另行输出的访问日志不属于本格式；默认屏蔽 Django 开发服务器重复的请求行，静态资源访问应由实际静态服务负责记录。

Agent 当次执行日志包含 `trace_id`／`span_id` 时，可与现有平台 Agent 监控关联。历史成功重放不会建立新的执行 Trace；本轮未向原 Span 白名单增加账号、HTTP ID 或敏感属性。

## 隐私与边界

Logger 的自由消息和参数被丢弃，未知事件会显示为 `application.log`；按 Logger、异常类型、栈位置和请求编号排查。需要更明确的原因时增加经过评审的固定事件，不能临时打印正文、密码或第三方返回值。Python warnings 同样不保存警告正文。

此次只修改日志输出：短信模拟接口原有响应仍含模拟验证码，一些旧接口仍返回原有异常说明；没有借本次改动统一修改它们的业务响应。日志文件不存放验证码，开发时可在浏览器中查看原有模拟接口响应；上线须关闭短信模拟模式。

现有命令进度、终端 Agent 调试报告、外部进程 stderr 和反向代理配置不自动变成安全 JSON 日志，不能将它们当作本轮已经完成脱敏的产物。外部日志采集、审计、自动清理与告警另行实施。
