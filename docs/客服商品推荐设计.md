# 客服商品推荐与记忆

推荐链路为：Django 认证与上下文装配 → Agent 结构化意向 → Python 合同/证据校验 → 商品服务匹配 → 数据库结果卡片。`support_ai/workflow.py` 不导入 ORM、不接收数据库句柄或查询回调；其他问答、售后分支也只消费应用层装配的文本数据。

## 输入与记忆

- 本轮问题先在本地脱敏。服务端只从当前认证买家的会话和偏好中读取上下文，不接受请求体自报用户、记忆或历史。
- 短期上下文取同一会话已提交且最近 24 小时内的最后 6 轮，用户原文和助手文本合计最多 6000 字；助手文本每轮最多 1500 字，只用于理解，不作为硬筛选条件证据。
- 长期记忆只保存买家主动填写的分类、品牌、商品名称关键词。每种最多 5 项，每项最多 40 字；不能保存预算、身份、订单或个人信息。保存/清除走独立接口，不由模型自动写入。
- 长期记忆现存于 PostgreSQL 的 `ai_storage.BuyerMemory`，MySQL 的旧偏好表仅作迁移来源；会话/短期上下文继续保存在 MySQL。Docker、数据库路由与迁移见 [PostgreSQL与pgvector配置](./PostgreSQL与pgvector配置.md)。
- 优先级为本轮明确要求、同会话有效条件、长期软偏好。存在分类或品牌硬条件时，对应长期偏好不参与排名。明确排除项始终过滤。
- “新对话”创建新的上下文范围；旧会话的脱敏记录保留用于恢复，没有自动删除历史的承诺。模型上下文 24 小时窗口与数据库记录保留是不同概念。

## 意向与匹配

`RecommendationIntent` 只允许 `SEARCH/CLARIFY`、`required/preferred/excluded`、`evidence` 和 `missing_fields`。不允许模型生成 SKU ID、SQL、ORM 路径或商品事实。

每个条件必须对应 `CURRENT` 用户原话、已知 `CONTEXT` 用户轮次或当前 `MEMORY` 偏好，且引用逐字匹配。长期偏好只能用于 `preferred`。来源引用与原文只能证明证据存在；自然语言理解仍依赖模型，真实语义质量需单独评测。

第一版硬条件支持分类、品牌、商品名称关键词、USD 单价区间和明确排除项。价格使用 Decimal。其他币种、总预算或未明确的单价单位进入固定澄清，不猜测汇率、数量和规格。功效、口感、认证等未有可靠字段的条件提示澄清。分类/品牌同组候选为“任一”，多个名称关键词为“全部”。受控分类别名支持常见中英茶类名称。

商品查询只取上架且有可用库存的 SKU。有 Inventory 台账时使用其可用量汇总；仅在没有台账时退回旧 SKU.stock，避免已预留库存因旧字段仍为正数而重新可售。本次不修改其他页面既有的库存显示逻辑。

软偏好仅影响排序。每次最多 4 个商品，依次按偏好匹配、推荐标记、销量、SKU ID 排序。没有满足硬条件的商品返回 `NO_MATCH`，不会回退成热门商品。名称、USD 单价、图片和固定详情链接全部来自 Python 数据投影，推荐分支不再调用总结/合规模型修改商品事实。价格和库存仍以下单校验为准。

## HTTP 与持久化

- `POST /v1/support/chat/`：接收 `message`，以及可选 UUID `request_id/conversation_id` 和非负整数 `expected_revision`。成功返回 `answer/intent/confidence/pii_redacted`，并增加 `conversation_id/revision/request_id`、`recommendations`、推荐状态和已校验的 `product_intent`。
- `GET/PUT/DELETE /v1/support/preferences/`：只读写当前买家偏好。PUT 接收 `categories/brands/keywords` 数组。
- `GET /v1/support/conversations/<uuid>/`：只恢复当前买家会话的最近 6 个已提交轮次。
- 同买家的相同 request_id + 相同完整载荷重放已保存结果；不同载荷返回 409。模型失败、合同失败或提交时 revision 冲突不提交新轮次。
- 模型等待不持有数据库事务。短提交事务再次检查所有权、请求幂等和 revision，再原子追加轮次及结果。SQLite 测试不能证明 MySQL 并发锁行为。
- 会话恢复和幂等重放显示当时保存的商品快照；不会重新生成或将历史价格描述为实时价格。

## 文件与运行

合同：`support_ai/contracts.py`；模型客户端：`model_client.py`；Agent 图：`workflow.py`；业务匹配：`recommendations.py`；长期记忆：`ai_storage/models.py`；会话与上下文：`support_ai/models.py/context.py`；HTTP：`views.py`。

新增 `support_ai/migrations/0001_initial.py`，运行应用前在目标环境执行：

```powershell
python manage.py migrate support_ai
python manage.py migrate ai_storage --database ai_storage
```

定向验证使用独立 SQLite 内存数据库和 Fake 模型，不连接配置的业务 MySQL、Redis或外部模型（真实向量 SQL 测试另使用 PostgreSQL 测试配置）：

```powershell
python manage.py test support_ai --settings=support_ai.test_settings --noinput
python manage.py makemigrations --check --dry-run --settings=support_ai.test_settings
node --check client/static/js/buyer-support.js
```
