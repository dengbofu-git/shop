# tea_saas 开发与运行环境配置

本文说明新环境的 **Python3.13 / Django5.2、统一PostgreSQL16＋pgvector、Redis、环境变量**。2026-11-02本地旧数据已完成独立迁移，见[迁移证据](sdd/evidence/2026-11-02-postgresql-unification/verification.md)。已有数据不能通过空库初始化代替迁移。与[项目接手指南](项目接手指南.md)和[PG配置](PostgreSQL与pgvector配置.md)配合阅读。

## 1. 环境总览

| 组件 | 版本/说明 | 是否必需 |
|------|-----------|----------|
| Python | **3.13**，Django5.2 LTS；依赖由requirements及constraints锁定 | 是 |
| PostgreSQL | 16及pgvector，业务和AI使用同一default连接 | 是 |
| Redis | **127.0.0.1:6379**，DB `0`（默认缓存）、DB `1`（购物车） | 是 |

外部服务（邮件、容联云短信、微博 OAuth、AI 客服、支付宝）在本地可通过 **Mock / 占位** 先跑通页面与大部分 API；见 [第 5 节](#5-环境变量-env)。

## 2. 安装 Python 依赖

项目仅维护 **`requirements.txt`**（已移除与之间功能重复的 `environment.yml`）。

### 2.1 使用 Conda（可选，Windows / macOS / Linux）

```powershell
cd e:\django\tea_saas
conda create -n tea_saas python=3.13 -y
conda activate tea_saas
pip install -r requirements.txt
```

更新依赖：

```powershell
conda activate tea_saas
pip install -r requirements.txt
```

### 2.2 使用 venv + pip

```powershell
cd e:\django\tea_saas
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2.3 依赖说明

- **Django5.2.18 + psycopg2-binary**：应用统一PostgreSQL；MySQL驱动仅在独立来源转移工具依赖中。Web与MCP均使用Python3.13；启动方式见[运行基线](Python与Django升级.md)。
- **django-redis**：会话/购物车等缓存；通过 `.env` 配置默认缓存和采购车地址，缺省分别使用 `redis://127.0.0.1:6379/0` 与 `/1`。
- **langchain / langgraph / langchain-openai**：买家智能客服（`support_ai`）。
- **python-dotenv**：启动时加载项目根目录 `.env`。

## 3. PostgreSQL

### 3.1 创建数据库

```sql
CREATE ROLE tea_saas LOGIN PASSWORD '替换为本地密码';
CREATE DATABASE tea_saas OWNER tea_saas;
```

连接新库后，由具备扩展权限的操作员执行`CREATE EXTENSION IF NOT EXISTS vector;`。`.env`中POSTGRES_*须与账号、库名、地址一致，TEA_SAAS_DATABASE_MODE=unified。本地Compose示例见compose.ai-storage.yml；已有卷不会因更改初始化环境变量自动创建新账号或重置密码。生产运行角色和迁移权限另行最小化。

### 3.2 新库迁移与基础数据

以下只用于新空库。已有MySQL及AI两库需按[独立迁移契约](sdd/architecture/postgresql-unification.md)冻结、备份、转移和验证，禁止直接更改连接指向空库后当作迁移完成。

```powershell
conda activate tea_saas
cd e:\django\tea_saas
python manage.py migrate
python manage.py seed_rbac
python manage.py create_super_admin
```

可选：

```powershell
python manage.py seed_demo_orders --merchant <茶企登录用户名>
```

## 4. Redis

1. 安装并启动 Redis，监听 **6379**。
2. Windows 可用 WSL、Memurai、或官方移植版；开发机需保证 `127.0.0.1:6379` 可连。
3. 未启动 Redis 时，依赖缓存/购物车的接口会报错——本地开发请先起 Redis。

通过 `.env` 的 `REDIS_CACHE_URL` 和 `REDIS_CARTS_URL` 分别设置默认缓存和采购车地址；未设置时继续使用本机 6379 的 DB0／DB1。Redis 开启密码认证时设置 `REDIS_PASSWORD`，该密码用于两个连接；留空适用于未启用密码的实例。若两端使用不同认证，可分别在各自 URL 中配置认证信息，特殊字符须进行 URL 编码，并将共享 `REDIS_PASSWORD` 留空。修改配置后重启 Django。

日志出现 `Authentication required` 或 `AuthenticationError` 表示 Redis 已响应但认证未通过，应核对本地密码和 URL，不要关闭服务认证或清空采购车数据。

## 5. 环境变量 `.env`

1. 复制模板：`copy .env.example .env`（PowerShell）。
2. **不要** 将 `.env` 提交 Git（已在 `.gitignore` 中忽略；`.env.example` 可提交）。

### 5.1 变量一览

| 变量 | 必填 | 说明 |
|------|------|------|
| `DJANGO_SECRET_KEY` | 是 | Django 密钥，生产环境使用长随机串 |
| `DJANGO_DEBUG` | 否 | 默认 `false`；本地建议 `true` |
| `DJANGO_ALLOWED_HOSTS` | 否 | 逗号分隔，如 `127.0.0.1,localhost` |
| `REDIS_CACHE_URL` | 否 | 默认缓存地址，缺省 `redis://127.0.0.1:6379/0` |
| `REDIS_CARTS_URL` | 否 | 采购车地址，缺省 `redis://127.0.0.1:6379/1` |
| `REDIS_PASSWORD` | 按实例要求 | Redis 共享认证密码；无密码实例留空，真实值不得提交 |
| `TEA_SAAS_DATABASE_MODE` | 否 | 默认unified；legacy仅供来源导出和明确恢复，不双写 |
| `POSTGRES_HOST` / `POSTGRES_PORT` / `POSTGRES_NAME` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | 是 | 统一PostgreSQL；不注册第二个AI数据库连接 |
| `JWT_SECRET_KEY` | 是 | 签发/校验登录 JWT |
| `ADMIN_INITIAL_PASSWORD` | 是 | `create_super_admin` 使用的 `admin` 初始密码 |
| `SUPPORT_API_KEY` | 是* | AI 客服 API Key（不用客服可填占位，调用会失败） |
| `SUPPORT_MODEL` | 是 | 模型名 |
| `SUPPORT_BASE_URL` | 是 | OpenAI 兼容 API 根地址 |
| `SUPPORT_THINKING` | 否 | 扩展参数，可留空 |
| `ALIPAY_*` / `FRONTEND_BASE_URL` | 是* | 真实支付需沙箱 AppId 与私钥；仅浏览可不测支付 |
| `ALIPAY_APP_PRIVATE_KEY` | 是* | **应用私钥 PEM 字符串**（非文件路径）；公钥文件见 `app_key/alipay_public_key.pem` |

\*：Django 启动时会 `os.environ['KEY']` 读取，**缺少任一键会 ImportError/KeyError**；本地用 `.env.example` 占位即可。

### 5.2 本地最小化建议

- `DJANGO_DEBUG=true`
- 短信验证码、邮箱激活／找回密码及微博认证接口已移除，不再需要 `EMAIL_*`、`SMS_MOCK_MODE`、`RONGLIAN_SMS_*`、`WEIBO_*` 配置。
- 支付宝、AI 可先填空或示例值，直到要测对应功能再改。
- 平台运营登录：执行 `create_super_admin` 后使用用户名 **`admin`** 与 `ADMIN_INITIAL_PASSWORD`。

| 路径 | 说明 |
|------|------|
| `client/static/` | 前端 CSS/JS/图片，`STATICFILES_DIRS` 指向此处 |

## 8. 常见问题

| 现象 | 处理 |
|------|------|
| 启动报 `KeyError: 'DJANGO_SECRET_KEY'`（或其它 env） | 确认根目录存在 `.env`，且键名与 `settings.py` 一致 |
| `django.db.utils.OperationalError` | PostgreSQL未启动、目标库/角色未创建或POSTGRES_*错误 |
| Redis 连接失败 | 启动 Redis；检查 6379 端口 |
| 平台运营 403 | `python manage.py seed_rbac` 后 `create_super_admin`，用 `admin` 登录 |
| 购物车/下单异常 | 确认 Redis DB `1` 可用 |
| CORS 报错 | 前端应通过 `127.0.0.1:8000` 同源访问；额外 origin 见 `settings.py` 中 `CORS_ALLOWED_ORIGINS` |

## 9. 生产部署注意（简要）

- `DJANGO_DEBUG=false`，`DJANGO_ALLOWED_HOSTS` 填真实域名。
- 使用独立强随机 `DJANGO_SECRET_KEY`、`JWT_SECRET_KEY`。
- Redis、PostgreSQL使用托管或内网地址，通过环境配置设置连接与认证信息。
- 配置 HTTPS 与支付宝生产参数；私钥与 `.env` 走密钥管理，勿进仓库。
