# tea_saas改动与交付

先定位仓库根目录，读取根目录 `AGENTS.md`、`docs/Git协作规范.md` 和 `versions/modules.json`。这些文件是当前规则来源；本技能只组织执行，不复制版本号、门禁状态或历史测试结论。适用子目录规则继续生效。

## 判断本次模式

- **IMPLEMENT**：用户要求实现或配置。明确本次目标、可改文件及验收行为，按需读取 `docs/sdd/` 中相关规格。没有明确的业务规则时先推进不依赖该规则的工作，避免替用户决定业务语义。
- **DELIVERY_ONLY**：用户只要求提交／推送已有改动。冻结实现，不趁交付修业务问题。允许授权范围内正常同步主干并处理含义明确的冲突；含义不明、历史迁移或超范围冲突停止说明。
- **CLOSEOUT**：用户要求本地核销／回收，或已授权交付进入合入后收尾。先读取[本地收尾 SDD](../../../docs/sdd/governance/local-delivery-closeout.md)，按现有授权执行；不扩大为自动合入、跨已有分支切换、删除远端对象或停服。

用户已授权的动作无需重复询问，但实现、提交、推送、创建 PR、合入、标签和部署分别判断，不能互相推导。交付前先完成可审阅的结果；不要把审批问题当作未做工作的替代品。

## 保护现场和识别归属

写入前检查当前分支、`git status --short`、`git worktree list --porcelain`，阅读实际 Diff（暂存和未暂存）及相关未跟踪文件。区分已有改动和本次增量。已有授权开发分支可复用；遵循根规则判断是否需要新建本地分支，不按聊天机械建分支。

使用模块清单最长路径匹配识别所有新增、修改和删除文件的归属；`tools/module_versions.py changed` 可帮助盘点，也会包含其他未提交工作，不能据此把它们都纳入本次交付。新增根路径／工具目录先登记归属。共享文件已有改动时精确增量编辑，保留原有内容。

需要隔离交付时先读[本地收尾 SDD](../../../docs/sdd/governance/local-delivery-closeout.md)，记录原工作区／分支、HEAD、暂存与未暂存差异、未跟踪文件、授权增量及回收目标；绑定后续交付 SHA 和 PR。恢复材料保存在持久主工作区的 `.scratch/git-delivery/<delivery_id>/` 或明确指定的持久目录，不留在待删除的临时区。优先复用适用现场，独立交付区只应用授权增量，不复制所有未提交工作作为新改动。

再次处理交付时，读取相关未完成收尾记录，对照最新 main 和实际合入证据识别已交付副本；未记录来源的存量先只读核对。旧 HEAD 下的 dirty 不等于新功能，同文件的新编辑、暂存意图和未知归属仍须保留。

## 实现与验证

实现变化同时更新相应模块版本及 changelog；分别评估后端与 web。纯文档不机械升版。依赖、运行配置和工具同样按真实影响评估，使用当前工作区版本递增，不覆盖别人已增加的版本。

按改动选择验证：

- 普通提交：检查分支、范围、实际 Diff、误纳入文件、冲突标记、`git diff --check`、模块归属和版本。不为提交隐式运行全量测试。
- 业务实现：运行能覆盖本次行为的定向验证；Django 检查、模板、静态资源、数据库或模型验证各按影响选择。语法通过不等于业务验收。
- Migration：历史文件不改写；新增迁移在真实后端的隔离库验证，禁止连接业务库试跑或自动回退。
- 真实模型评测：先核对本次授权的数据范围、目标服务和调用范围；不能继承历史报告中的调用授权。

记录实际命令、环境、结果和覆盖范围；历史报告只作参考，不能冒充本次通过。失败、未执行和不适用分别说明。

## 按授权交付

提交时只精确暂存本次授权文件；同一文件混有其他工作时核对具体 hunk，无法安全拆分则说明。提交信息使用根规范的中文格式。禁止 `git add .`、自动 stash、reset、强推、改写共享历史或绕过 hook。

推送前盘点全部 worktree，确认当前分支工作区干净，获取最新 `origin/main` 并正常 merge 到源分支；审阅完整待交付 Diff，运行 `python tools/git_policy.py verify --base origin/main` 和按影响需要的业务验证。将证据绑定最终源 SHA 和 main SHA；合并改变被测内容时重新验证。门禁失败按原因处理，不能 `--no-verify` 或改配置绕过。

需要 PR 时读取 `.github/pull_request_template.md`，目标为 `main`，保留“概要、改动、验证”，填真实 SHA、模块版本、命令和结果。仅授权推送时只提供可复制 PR 文案，不创建或合入。未核实 GitHub 实际保护配置时，不声称远端强制门禁已生效。

## 本地收尾与恢复

在隔离交付、再次交付或 CLOSEOUT 时按[本地收尾 SDD](../../../docs/sdd/governance/local-delivery-closeout.md)执行；规则、状态取值及验收以该文为准，不在技能中另建一套。

1. 推送／建 PR 后记录远端事实。PR 尚未合入时将收尾记为 `waiting-merge`，报告当前请求结果与后续动作；不等待未授权合入，不创建未请求的定时任务。
2. 确认合入后核对最新 main、PR、合入方式和 SHA。Squash／rebase 不能只用源 SHA 祖先关系判断；主干后续演进不能被本地旧副本重新覆盖。
3. 分别核对原工作区与临时资源。按来源增量区分已交付副本、主干已演进、未交付、混合及未知内容；“已交付事实登记”不代表原现场已经核销。
4. 脏原工作区先形成保留增量、暂存意图、恢复材料和执行前提的可审阅计划。缺少经验证的核销工具或无法证明安全时保持只读，不即席构造批量反向补丁、整文件覆盖或清场脚本；记录具体阻塞，继续独立安全项。工具可用时也须在写入前重核对快照和授权，现场变化则重新计划。
5. 回收只处理本次管理且在授权范围内的对象。合入、归属、占用、未跟踪／忽略文件、运行服务与挂载、恢复材料及实际路径边界均须核实。使用受支持的托管归档或正常 Git 回收命令；保护拒绝时保留并说明，禁止强删。其他任务的存量只列清单，不自动接管。
6. 执行后复核原工作剩余增量、worktree 注册、本地分支和保留材料。中断后从记录恢复并重新核对现场，不能照旧计划删除；已完成步骤不重复执行。

最终说明：本次变化、验证及未覆盖范围；提交／推送／PR／合入／部署的实际结果；原工作核销、临时工作区与分支回收的分别结果。保留或阻塞项写明对象、原因和恢复条件；无待回收资源记为不适用，不为流程另建现场。未核销的已交付副本仍须报告待处理，不能以“PR已合入”宣称本地收尾完成。不要泄露配置凭据。
